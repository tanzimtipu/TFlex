# Implementation plan: all dialogs, toolboxes and menus

1. **Inventory and classify.** Search the repository for dialog/modal, popover, menu/contextmenu, tooltip, portal and canvas-selection action components using the actual framework. Catalogue component path, feature, opener, command IDs, current primitive, modal status, capability rules, commit/cancel behavior, native dependencies and duplicate styling. Include hidden/rare surfaces, not just screenshots. Produce surface-inventory.csv; identify native Windows dialogs that remain native. Confirm extract/split source effects, stamp save behavior and textbox Confirm semantics from handlers.

2. **Establish shared foundations.** Extend existing Quiet Precision tokens with interaction-surfaces.tokens.json; retain Icons, Buttons, Panels and Dock conventions plus colorful tab identities scoped to tabs. Create/reuse standard primitives for TaskDialog, PreviewTaskDialog, ContextToolbox, PropertyPopover, CommandMenu and Tooltip. Define header/body/footer slots, content-driven widths, bounded body scrolling, portal/layer policy, focus/dismiss behavior and reduced motion. Use framework accessibility primitives and platform APIs. Avoid replacing reliable existing primitives solely for new CSS.

3. **Pilot representative tasks.** Migrate Extract/Split, Create PDF from images, Stamp, annotation/text selection actions and File menu. Use actual state and commands; preserve every action absent from the mock. Verify a short form, a list/preview task, a long body, a nonmodal canvas toolbox and a multi-group menu. Show source context, clear verbs, validation and next-step placement cues. Get concrete screenshots for light/dark and constrained desktop sizes. Resolve primitive defects before broad rollout.

4. **Migrate the complete inventory.** Move each discovered overlay onto the relevant shared primitive using feature adapters. Remove redundant surface styles and obsolete tokens after confirming all consumers moved. Route every repeated command through the registry. Keep specialized workflows' engine state, permissions, undo and existing confirmation policy. Make native/system exceptions explicit in the inventory rather than forcing a web-styled replacement.

5. **Validate interaction and presentation.** Run relevant existing tests. Add meaningful tests for shared focus/dismiss contracts, task validation, true capability/busy guards, and clipping/collision regressions where those are otherwise untested. Manually test Windows DPI, native file-picker return, zoom/scroll canvas anchors, keyboard and screen-reader behavior, IME and multiline comments. Test empty/populated/invalid/busy/error/success states using real state, long translated strings and page-edge positions. Verify inventory coverage and command reachability.

6. **Deliver a reviewable change.** Report migrated surfaces and remaining exceptions, final command mapping, tests and limitations. Include representative before/after screenshots with actual content. Keep the resource specification/prompt synchronized with implemented behavior. No publishing or merging is part of this design handoff.

Completion criterion: every in-app overlay in the audited inventory uses the shared visual family or a documented platform/task exception, without loss of commands, focus behavior, draft state or document semantics.
