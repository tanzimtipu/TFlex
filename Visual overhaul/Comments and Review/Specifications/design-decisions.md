# Comments and Review — Thread Stream

Use one **Thread Stream** for real annotations and replies. The left navigator owns the list; the right inspector owns the selected annotation's editable properties. A floating editor is for the current draft / nearby contextual controls, not a third duplicate full comments list. The Page Ledger alternative groups the same annotations by destination page for page-oriented review.

Each annotation row shows actual author if present, annotation type, destination and relevant status. Use initials only when a real author exists; otherwise show a neutral annotation glyph. The prototype's people and messages are fixtures. Do not invent collaborators, timestamps, unread counts or cloud synchronization. If the existing model lacks resolved state or threaded replies, map the design to actual PDF annotation metadata or scope those additions separately. Do not hide all unsupported state in an opaque private store and claim interoperability.

Use 14 px comment body, 13 px author / action text and 12 px page / type / time metadata. A 32 px avatar is optional, neutral and subordinate. Quote selected text only when it is reliably associated with the annotation; otherwise label its actual type. Long comments wrap and expose full content. A compact preview may expand on selection, preserving list scroll position. Avoid a repeated rainbow swatch strip on every row; color controls belong to the selected item's properties.

Selecting a row reveals its actual page / rectangle / destination, then focuses the appropriate contextual inspector without stealing keyboard focus unnecessarily. Canvas selection updates the selected row via stable annotation identity. Filtering All / Open / type uses actual states and preserves drafts. A filter must not erase an unsent reply or selected annotation. When no annotations match, distinguish an empty document from an empty filtered result and offer a meaningful supported action.

Reply / edit controls have clear Apply / Cancel or post semantics; keep unsent content local to that annotation and preserve it on recoverable errors. Resolve / Reopen exists only if backed by real state and save/export behavior. Delete affects the intended annotation, preserves confirmation / undo policy and does not remove every selected item's replies accidentally. Multi-select properties expose Mixed and deliberately scoped changes.

Import / Export comments reuses existing FDF handlers, surfaces supported format / compatibility limits and reports partial or failed imports. Imported author/date values remain source data, not authenticated identity claims. Document permissions, signatures and read-only documents govern every mutation. Preserve native annotation IDs / relationships and avoid duplicate annotations on retry.

Acceptance: empty / populated / filtered lists, many annotations, long text, real author absent, supported replies / resolve, draft retention, canvas synchronization, import / export round-trip, duplicate import policy, undo, tab switching, read-only permissions and keyboard / screen-reader access. Keep controls above page content and clear of the dock and viewing footer.

## Shared visual and implementation rules

This category extends Quiet Precision. Surface / canvas: #FFFFFF / #F5F6F8 in light, #20232B / #171A21 in dark. Main text: #485164 / #B8C0D0; strong: #232A38 / #EEF1F7; small supporting text: #667085 / #929BAC. Boundary: #E1E4EB / #3B414E; interactive violet: #7050D6 / #B9A4FF; selected surface: #F0EBFC / #302740. Read the unified semantic tokens and the Consistency Corrections folder. Document-tab identities remain colorful and stable per session, confined to the rail.

Use a 4 px spacing grid, 9 px control radius, 12–14 px floating surface radius, 16–24 px content spacing and 140 ms emphasis transitions. Attached panels use hairline boundaries, not floating shadows. UI typography follows the existing Typography folder. Original icons follow the 24-unit / 1.65 round-stroke grammar; this reference uses host Lucide icons for illustration. Never replace PDF fonts or pixels with UI tokens. Reduce motion and high contrast apply across the category.

First audit all relevant entry points, existing handlers, source data, capability predicates, settings / document stores, state transitions and any engine constraints. Reuse command / menu / dialog / form primitives; do not introduce parallel stores or CSS overrides at each call site. Only render information the app can support truthfully. This handoff designs behavior for capabilities to verify, not evidence that every pictured feature already exists.

Implementation phases: inventory and state contracts; shared primitives / tokens; category migration across every entry point; asynchronous and cross-document correctness; accessibility / performance; real app regressions and visual review. Preserve document content, session identity, undo history, keyboard bindings, permission checks, save / close / cancellation policies and native Windows chrome. Test all supported themes, long and localized labels, restored / maximized windows, 200% scaling, keyboard and relevant error / empty states.

## Reference limits

Both visual alternatives are local interaction prototypes. Filenames, people, comments, form labels, matches, progress, output geometry and command results are illustrative unless specifically documented as installed-app observations. They do not run OCR, PDF editing, conversion, save, print, mail, collaboration or system preference changes. The prototype's short fixture arrays and state handlers are not production data models. Example scenario controls such as Continue / Show failure on the Activity reference exist solely to inspect state styles and must not become product commands. Native dialogs, screen-reader tree semantics, forced colors, drag transforms, focus trapping and engine integrations must be implemented and tested with the real application.
