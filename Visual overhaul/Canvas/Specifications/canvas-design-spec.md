# Canvas — Paper Stage

Use a quiet, cool neutral document stage, clear page boundaries and restrained shadows. Remove broad decorative background bands or unrelated glass effects from the document area. A predictable canvas lets the colorful tabs and violet workspace cues remain useful without competing with page content.

Proposed canvas light #ECEFF4, dark #151820; actual document pixels retain their original colors. Page edges are square and follow actual PDF CropBox/MediaBox/rotation, not the rounded UI surface convention. A 1px neutral exterior boundary and a two-layer soft shadow clarify white pages on light canvases. Proposed shadow: 0 2px 4px #232A3808 plus 0 12px 24px #232A380D in light mode; #00000020/#00000030 in dark. Shadow is UI chrome outside the page and must not enter exported/printed content or selection coordinates. Prefer a renderer wrapper/equivalent platform layer without modifying the document bitmap.

Center document geometry within the **available editor viewport**, excluding siderail, open panels/inspector, top chrome and viewing footer. Use roughly 24–32px margins at fit scale, 24px continuous-page gap and an 8–12px spread gap. Exact gaps should remain consistent logical spacing while page scale changes; preserve actual page aspect ratios. Single-page, continuous, facing-pages/book and grid modes must reflect the existing renderer's distinct semantics. The two-page schematic preview does not authorize rewriting the page-layout engine or automatically stacking actual spread pages at narrow widths.

At zoom above fit, allow real canvas scrolling/panning rather than shrinking content to preserve decorative margins. Keep the active view anchor stable when zooming or panels change. Use the existing renderer's coordinate transforms for selection, hit testing, page overlays and toolbox positioning. Preserve scroll position, current page, PDF links, text selection, form interaction, keyboard navigation and virtualized/lazy page rendering. Recalculate fit modes when viewport dimensions, page rotation or layout mode changes; manual zoom should follow current product behavior without unexpected resets.

Dark UI must not invert PDF artwork, signatures, annotation colors or images by default. If an existing document reading/night mode changes document appearance, keep it a separate explicit preference with faithful export/print behavior. The preview's page has an intentional light-dark(#FFFFFF,#FFFFFF) paper token because document whites remain white across UI themes; real pages may have any artwork/background. Application typography tokens must not replace embedded PDF fonts. Never fabricate an editable document by rendering UI text over a PDF screenshot.

Reserve space for the proposed viewing footer and floating command dock. The dock sits above the footer within safe viewport bounds, with sufficient bottom scroll inset so page content can move clear of overlays. No overlap between page navigator, zoom/view controls, dock, system scrollbars or panels. Canvas empty/loading/error states use actual renderer feedback and retain useful navigation; no animated decorative background while editing. Page render indicators must not misrepresent document contents or hide failures.

Acceptance: actual mixed-size/rotated pages; single/continuous/spread/grid modes; fit-page/fit-width/manual zoom; high zoom scroll; panel open/close; tab switching; renderer failures; text/form/canvas interactions; large documents/virtualization; DPI; light/dark; original export/print fidelity. Test transformed hit locations against real pages, not only screenshot alignment. Keep canvas changes limited to appearance/layout wrappers unless a demonstrated renderer defect requires a separate fix.
