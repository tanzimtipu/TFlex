# Viewing Controls — View Strip

Unify the existing bottom-left page navigation, bottom-right zoom/pan controls and top-right layout/book controls into one coherent viewing system. Recommended: a dedicated 44–48px footer inside the available editor area, below the document viewport, using three groups: page navigation left, flexible space, zoom and view/tool access right. The preview shows a compact contained strip; production stretches/aligns groups using real editor bounds. The command dock floats above this footer with at least 16px separation and adequate scroll inset. Do not place both controls on the same bottom baseline and hope they fit.

Page group: Previous, editable actual page position/label and total, Next. Preserve the distinction between physical page index and PDF page labels. Expose descriptive names where the document uses nonnumeric labels. Validate against actual count; don't silently clamp a mistyped page or lose the current location. Support Enter/commit according to existing behavior and understandable inline feedback. Disable Previous/Next truthfully at boundaries; navigation stays responsive to scrolling, renderer events and tab switching.

Zoom group: expose current scale and fit modes through a compact selector or the existing accessible zoom primitive. Preserve current zoom-in/out steps, permitted min/max, typed percentage input, shortcuts and mousewheel behavior. The schematic selector only shows fit-page, fit-width and a few fixed percentages; production must retain all existing controls. Fit mode is persistent view intent, while the computed percentage is measured from available viewport/page geometry; don't treat “Fit page” as a fixed number. Maintain a coherent model with mode plus actual scale. Recompute active fit when viewport/layout/rotation changes. Display real percentage as appropriate without implying output resolution or print scaling.

View group: preserve single-page, continuous/facing-page, grid, Book View and other actual modes after auditing their handlers. The preview's single/spread/grid three-way switch is schematic and may not map one-to-one to current renderer modes. Book View's binding/cover behavior must remain distinct if the app currently supports it. Pan is a tool state, not a page-layout mode; enabling it must follow existing canvas-tool exclusivity and preserve forms/text interactions. Fullscreen/focus view and fit-width/fit-page commands remain reachable with explicit accessible names, without conflating them.

Use opaque surfaces, 12px group surface radius, 8–9px control radius, 16px icons, 32px fine targets and 44px coarse targets. Use 12–14px labels and tabular figures for page/zoom values. Selected layout and tool states use shared violet soft fills; ordinary view commands remain neutral. Preserve visible focus, stable disabled state and tooltips on focus/hover. Compact grouping should not hide essential values or force guessing from arrows. Use actual registry accelerators; don't invent shortcuts.

Alternative Separated Groups maintains an upper layout group and lower navigation/zoom group. This costs extra vertical space and is only a fallback when integration constraints justify it. Production should use measured overflow/more-menu routing and minimum supported window width rather than copying the mock's broad wrapping into unpredictable full-height footer chrome. Keep all existing actions accessible at constrained widths. Footer visibility/auto-hide follows established app policy; don't introduce disappearing controls while interacting or cover the document with a new transient bar.

Integration: a shared view controller drives all current menu/dock/keyboard controls, rather than parallel UI-local state. Coordinate page indices, labels, fit mode, scale, layout and tool state without engine refactors. Prevent stale state when rapidly switching documents. Update viewport measurements and dock/overlay positioning for footer height. Accessibility semantics differ for layout selection, menu controls and tools; use appropriate framework primitives.

Acceptance: page boundaries and invalid entry; labeled pages; scroll-driven current page; mixed dimensions/rotation; all existing zoom entry/steps/limits; fit recomputation; every existing view mode and tool; keyboard/screen reader; pointer/touch; short/narrow restored windows and DPI; no footer/dock/page overlap. Verify the real renderer state and location anchor before claiming a control operates correctly. The preview only demonstrates state/validation and does not zoom or navigate actual PDFs.
