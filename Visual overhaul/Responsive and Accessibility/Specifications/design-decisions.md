# Responsive and Accessibility — Adaptive Shell

Treat responsiveness and accessibility as cross-component behavior, not an optional final skin. **Adaptive Shell** keeps the rail, canvas and one relevant inspector usable while adapting panel visibility to available space. The Focus Layout alternative intentionally prioritizes the document while retaining reachable navigation / inspector controls. Neither hides a feature merely because its button does not fit.

Measure the actual document viewport after native captions, title row, tab rail, siderail, attached panels, dock and footer. Use layout tokens / container measurements rather than scattered viewport constants. The colorful document rail keeps readable minimum tab widths and a complete All tabs switcher. The dock centers inside the document viewport and puts overflow commands in More. A hidden inspector / navigator has a labeled reopen control; do not collapse both with no recovery path.

Use explicit precedence: preserve native Windows captions, current document identity and essential file commands; preserve workspace access; prefer one attached panel in constrained windows; use an accessible drawer for secondary detail; retain page navigation / zoom controls; overflow secondary dock actions. Switching to Focus is a user choice. Automatic layout changes must not discard widths, collapsed states, drafts, selections or user preferences. Restore preferred geometry when space returns. Preview vertical stacking at 320 px is illustrative; real desktop minimum size and native chrome must be audited.

All UI uses logical pixels, honors Windows text / display scaling and supports 200% without overlapping labels / targets. Controls provide at least 32 px fine-pointer targets and around 44 px coarse-pointer targets, with no invisible hit-area overlaps. Do not shrink fonts to solve overflow. Long labels and localized strings reflow or ellipsize with full accessible names and a focus / hover tooltip. Truncated text must not become inaccessible. Distinguish OS display scale from app UI scale and PDF zoom; they are different settings.

Use framework-native semantic tabs, trees, menus, dialogs, toolbars, inputs and separators. Define a coherent focus order across chrome, navigation, canvas, dock and inspector. Keep focus visible independently of selected / hover state. Escape closes the topmost transient surface and restores its correct opener; it must not discard unrelated document edits. Dialogs trap focus, inert the background and expose their title / description; attached panels do not trap focus. Avoid nested interactive elements. Existing shortcuts retain scope and must not conflict with typing, IME or screen-reader keys. A shortcuts reference uses actual registered accelerators.

Light / dark semantic contrast meets 4.5:1 for small text and 3:1 for meaningful non-text boundaries / states where applicable. High contrast uses forced-color system values, visible markers / checkboxes / labels and solid surface boundaries; verify native focus survives custom style layers. Never depend on a specific violet or unique tab hue to identify status. Reduced motion removes nonessential transitions and decorative Home motion; no other component begins looping merely to look modern.

Build a regression matrix rather than mirroring markup with superficial tests: real commands and drafts at restored / maximized / minimum window sizes, 100/125/150/200% Windows display scaling, 200% text scaling, keyboard-only use, screen reader, high contrast, reduced motion, touch and mixed-DPI monitor changes. Test PDF viewport anchors separately from UI layout. The preview's high-contrast switch is a visual comparison only; production must use the operating system's actual forced-colors path.

## Shared visual and implementation rules

This category extends Quiet Precision. Surface / canvas: #FFFFFF / #F5F6F8 in light, #20232B / #171A21 in dark. Main text: #485164 / #B8C0D0; strong: #232A38 / #EEF1F7; small supporting text: #667085 / #929BAC. Boundary: #E1E4EB / #3B414E; interactive violet: #7050D6 / #B9A4FF; selected surface: #F0EBFC / #302740. Read the unified semantic tokens and the Consistency Corrections folder. Document-tab identities remain colorful and stable per session, confined to the rail.

Use a 4 px spacing grid, 9 px control radius, 12–14 px floating surface radius, 16–24 px content spacing and 140 ms emphasis transitions. Attached panels use hairline boundaries, not floating shadows. UI typography follows the existing Typography folder. Original icons follow the 24-unit / 1.65 round-stroke grammar; this reference uses host Lucide icons for illustration. Never replace PDF fonts or pixels with UI tokens. Reduce motion and high contrast apply across the category.

First audit all relevant entry points, existing handlers, source data, capability predicates, settings / document stores, state transitions and any engine constraints. Reuse command / menu / dialog / form primitives; do not introduce parallel stores or CSS overrides at each call site. Only render information the app can support truthfully. This handoff designs behavior for capabilities to verify, not evidence that every pictured feature already exists.

Implementation phases: inventory and state contracts; shared primitives / tokens; category migration across every entry point; asynchronous and cross-document correctness; accessibility / performance; real app regressions and visual review. Preserve document content, session identity, undo history, keyboard bindings, permission checks, save / close / cancellation policies and native Windows chrome. Test all supported themes, long and localized labels, restored / maximized windows, 200% scaling, keyboard and relevant error / empty states.

## Reference limits

Both visual alternatives are local interaction prototypes. Filenames, people, comments, form labels, matches, progress, output geometry and command results are illustrative unless specifically documented as installed-app observations. They do not run OCR, PDF editing, conversion, save, print, mail, collaboration or system preference changes. The prototype's short fixture arrays and state handlers are not production data models. Example scenario controls such as Continue / Show failure on the Activity reference exist solely to inspect state styles and must not become product commands. Native dialogs, screen-reader tree semantics, forced colors, drag transforms, focus trapping and engine integrations must be implemented and tested with the real application.
