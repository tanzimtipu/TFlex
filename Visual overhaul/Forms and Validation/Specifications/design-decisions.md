# Forms and Validation — Guided Fill

Separate **Fill form** from **Edit form fields**. Guided Fill helps complete existing PDF form values with a visible current field and useful required-field summary. The Field Inspector alternative shows the current field's supported properties and value controls. Use real AcroForm / supported form-engine metadata; never synthesize UI labels or required fields from arbitrary nearby page text without an established extraction flow.

A fill panel shows the document / page scope, field label, value, actual required state and error associated with the field. The prototype's name / email fields are examples, not an assertion about the bundled form. Document and page totals are distinct. “Required” must come from PDF semantics, and “complete” means the supported validation constraints passed, not merely non-empty. Email validation appears only when that field actually has an appropriate constraint. Do not add email delivery or remote submission capability merely because an address exists.

Use the shared field primitives: 13 px labels, 14 px values, 12 px guidance, 38–40 px input heights, 9 px corners and 16 px vertical rhythm. Associate labels, descriptions and errors programmatically. Place concise validation beneath the field, with an error icon / text and danger boundary. Explain how to correct it. Do not rely on color. Preserve the value after errors and move focus to the first invalid field only after an explicit validation / completion attempt, not on every keystroke.

For existing text, multiline, checkbox, radio, choice, date or signature field types, use the correct native / framework primitive and engine semantics. Preserve export values, option labels, radio grouping, multiselect behavior, field name, appearance streams, read-only flags and document permissions. If a field type is unsupported, show a useful read-only explanation; do not silently convert it. Tab / Shift+Tab must follow the document's supported field order. Link canvas field focus and inspector focus without endlessly cycling focus.

Editing fields is a distinct operation: name, type, tooltip, required / read-only flags, choices, alignment and other supported properties apply through existing APIs and undo history. Show Mixed for multi-field properties where appropriate. Changing a type or flattening fields may discard interactivity and must preserve the existing consequence / confirmation flow. Ordinary filling must not flatten a form. Avoid claiming a signature is verified or legally valid from the presence of a signature graphic.

Persist values through existing save flows and regenerate appearances correctly. Validate actual output by reopening the PDF in supported readers / engine tests. Repeated field names, widgets across multiple pages, calculated fields and signed / encrypted forms need explicit regression fixtures. If the app executes PDF form scripts, preserve its existing policy; a visual migration must not enable arbitrary scripting.

Acceptance: blank / complete / invalid values, all supported field types, localization / IME, long text, required / read-only flags, repeated fields, keyboard order, save / reopen, undo, permissions, calculation policy, multi-page and scaled / rotated views. Inline form controls never change the underlying PDF's typeface merely because UI typography changes.

## Shared visual and implementation rules

This category extends Quiet Precision. Surface / canvas: #FFFFFF / #F5F6F8 in light, #20232B / #171A21 in dark. Main text: #485164 / #B8C0D0; strong: #232A38 / #EEF1F7; small supporting text: #667085 / #929BAC. Boundary: #E1E4EB / #3B414E; interactive violet: #7050D6 / #B9A4FF; selected surface: #F0EBFC / #302740. Read the unified semantic tokens and the Consistency Corrections folder. Document-tab identities remain colorful and stable per session, confined to the rail.

Use a 4 px spacing grid, 9 px control radius, 12–14 px floating surface radius, 16–24 px content spacing and 140 ms emphasis transitions. Attached panels use hairline boundaries, not floating shadows. UI typography follows the existing Typography folder. Original icons follow the 24-unit / 1.65 round-stroke grammar; this reference uses host Lucide icons for illustration. Never replace PDF fonts or pixels with UI tokens. Reduce motion and high contrast apply across the category.

First audit all relevant entry points, existing handlers, source data, capability predicates, settings / document stores, state transitions and any engine constraints. Reuse command / menu / dialog / form primitives; do not introduce parallel stores or CSS overrides at each call site. Only render information the app can support truthfully. This handoff designs behavior for capabilities to verify, not evidence that every pictured feature already exists.

Implementation phases: inventory and state contracts; shared primitives / tokens; category migration across every entry point; asynchronous and cross-document correctness; accessibility / performance; real app regressions and visual review. Preserve document content, session identity, undo history, keyboard bindings, permission checks, save / close / cancellation policies and native Windows chrome. Test all supported themes, long and localized labels, restored / maximized windows, 200% scaling, keyboard and relevant error / empty states.

## Reference limits

Both visual alternatives are local interaction prototypes. Filenames, people, comments, form labels, matches, progress, output geometry and command results are illustrative unless specifically documented as installed-app observations. They do not run OCR, PDF editing, conversion, save, print, mail, collaboration or system preference changes. The prototype's short fixture arrays and state handlers are not production data models. Example scenario controls such as Continue / Show failure on the Activity reference exist solely to inspect state styles and must not become product commands. Native dialogs, screen-reader tree semantics, forced colors, drag transforms, focus trapping and engine integrations must be implemented and tested with the real application.
