## Phase 92 - Dialog and window renovation: one reusable modern dialog shell (operator request via parent TFL-481 / driver TFL-513, 2026-10-03)

**Operator request (product terms, TFL-481 / TFL-513):** every dialog box and auxiliary window should look and behave like part of one modern, professional product. Today they are unstructured: inconsistent spacing, cramped text, ragged label/field alignment and ad-hoc button placement. Renovate the complete set so each dialog/window has one strong, consistent structure and a clear visual hierarchy. Offline only; no network feature.

**Relationship to the shipped dialog infrastructure (Phases 13/14.1/15/17/20/40/59/71) and to Phase 91.** Dialog motion and a class convention already exist: `AnimatedDialog` (`src/renderer/components/AnimatedDialog.tsx:23-91`), the `TfBackdrop`/`TfDialog`/`TfSheet` wrappers (`src/renderer/components/motion/TfMotion.tsx:190-216`) and the `.modal-dialog` / `.modal-header` / `.modal-body` / `.modal-footer` CSS (`styles.css:5841-6045`). But there is **no reusable shell component**: every dialog hand-rolls its own root markup, its own Esc/focus/backdrop effects (e.g. `ConfirmDialog.tsx:57-79`, `SaveAsDialog.tsx:76-94`) and its own spacing, so structure and alignment drift. Phase 92 adds the missing **one shell** and adopts it everywhere. It is a **renderer-only chrome/structural phase**: it owns the shell, the dialog typography/spacing/control-height/icon-size/radius tokens and the label/field/help/validation grid. It does **not** own the button taxonomy (Phase 91 owns button categories and every button's visual treatment) and does **not** redesign the main-window title bar or command bar (Phase 91 owns those surfaces). Where a dialog's buttons are touched, Phase 92 keeps whatever `.btn` class is present and only standardises **placement/order/hierarchy** in the footer. No main-process code, no `src/shared/`, no IPC, no settings channel, no new document model, no network.

**Dialog/window inventory (the complete adoption set).** Modal dialogs (35): `AboutDialog`, `AccountsDialog`, `AuditSpaceDialog`, `BatesDialog`, `BlankPagesDialog`, `CloseTabPromptDialog`, `CommentExportDialog`, `CommentImportDialog`, `ConfirmDialog`, `CropPagesDialog`, `CreateFromImagesDialog`, `DeletePageDialog`, `DocxExportDialog`, `DocumentInfoDialog`, `EncryptDialog`, `ExportDialog`, `FillFromCsvDialog`, `FormDataIoDialog`, `InsertPagesDialog`, `MergeDialog`, `OcrDialog`, `OfficeExportDialog`, `OptimizeDialog`, `PasswordPromptDialog`, `PreferencesDialog`, `RenumberPagesDialog`, `ReplacePagesDialog`, `SaveAsDialog`, `SanitizeDialog`, `SignatureManagerModal`, `SplitDialog`, `StampDialog`, `TextExportDialog`, `UpdatePromptDialog`, `ValidateDocumentDialog`, `WatermarkDialog`, plus `forms/FlattenConfirmDialog`. Auxiliary windows: `src/renderer/print-window/PrintWindowApp.tsx` (the print window) and the detached document window (`src/main/window.ts:592 createDetachedWindow`, which loads the same App renderer). Popovers, flyouts, palettes, the command palette and the annotation colour palette are NOT dialogs and are out of scope (Phase 91 owns them).

**CTO RULINGS:**

1. **Scope and files.** Renderer only. New: `src/renderer/components/DialogShell.tsx` (the shell) and `test/unit/renderer/dialogShell.test.tsx`. Modified: `src/renderer/styles.css` (dialog tokens in the `:root` block `:15-491` and the dialog CSS `:5841-6045`), the `*Dialog.tsx` inventory above, `src/renderer/forms/FlattenConfirmDialog.tsx`, `src/renderer/signatures/SignatureManagerModal.tsx`, `src/renderer/print-window/PrintWindowApp.tsx`, and the existing per-dialog unit tests. No other areas. No `src/main/`, no `src/shared/`, no `src/preload/`, no `package.json` dependency change, no IPC, no settings field.
2. **One shell is the single source of structure.** `DialogShell` renders exactly the shipped modal DOM so no selector or e2e hook moves: `TfBackdrop` (class `modal-backdrop`, backdrop-close via `useBackdropClose`) wrapping `TfDialog` with class `modal-dialog dialog dialog-shell` plus one size modifier, then `.modal-header` (optional leading icon, `<h2 class="modal-title">`, close button `.modal-close` with `aria-label="Close dialog"`), `.modal-body`, and `.modal-footer` (only when actions/footer are supplied). The shell owns Esc-to-close, initial focus and the backdrop-close pair **once**, so adopters delete their duplicated effects. Every extra prop (including every `data-*` hook already on a dialog root) is forwarded to the `TfDialog` root unchanged, so no existing e2e selector breaks.
3. **Shell API (frozen; adopter briefs consume it verbatim).** `interface DialogShellProps { open: boolean; title: string; titleId?: string; onClose?: () => void; blockBackdropClose?: boolean; closeDisabled?: boolean; closeTestId?: string; icon?: ReactNode; size?: 'sm' | 'md' | 'lg' | 'tool'; actions?: DialogAction[]; footer?: ReactNode; bodyClassName?: string; className?: string; testId?: string; draggable?: { controlsSelector: string }; surface?: 'dialog' | 'sheet'; closeAriaLabel?: string; children: ReactNode }` and `interface DialogAction { key: string; label: string; icon?: ReactNode; variant: 'primary' | 'secondary' | 'tertiary' | 'danger'; onClick: () => void; disabled?: boolean; default?: boolean; testId?: string }`. `onClose` omitted = the dialog must be answered (no backdrop close, no close X, no Esc). `size` maps to fixed classes: `sm` = min(380px, 100vw-32px), `md` = the existing 460px, `lg` = the existing 720px (`modal-dialog-wide`), `tool` = the existing `modal-dialog-tool` (near-square, capped height). `actions` render in the footer **right-aligned, left-to-right in the given order, primary right-most**, each as `<button class="btn btn-primary|btn-secondary|btn-ghost|btn-danger">`; `default: true` marks the primary that receives initial focus; `data-dialog-action={key}` and optional `testId` are emitted so the adopter's existing hooks move onto the action. An optional `icon` (Phase 92 chunk D1, 2026-10-03) renders inside the action button immediately before its label, so an adopter that shipped a leading glyph on its primary action (e.g. the crop/stamp/delete confirms) keeps it after adoption. `footer` supplies a custom node only for a dialog whose footer is not a plain action row. `blockBackdropClose` (default false) makes the backdrop ignore clicks while true (busy states) while Esc and the close X still work; `closeDisabled` (default false) disables the header close X (for busy states) while Esc and the backdrop-close guard stay as configured; `closeTestId` sets `data-testid` on the header close X so an adopter's existing close hook survives. `draggable` (Phase 92 chunk D3a, 2026-10-03) is opt-in: when set, the shell makes the dialog root a DEF-147 floating-window drag handle - a press on chrome not matching `controlsSelector` starts a viewport-clamped move, the root gains `modal-dialog-dragging` while dragging, and the offset folds into the TfDialog motion `x`/`y`; unset leaves the DOM, classes, ref wiring and motion targets byte-identical to before. `surface` (Phase 92 chunk E2a, 2026-10-03) is opt-in: `'dialog'` (default) renders the modal chrome; `'sheet'` renders the shipped sheet chrome (`.sheet-backdrop` > `TfSheet` with `.sheet-header`/`.sheet-title`/`.sheet-close`/`.sheet-body`) so a sheet-surface adopter keeps its DOM. `closeAriaLabel` (default `'Close dialog'`) sets the close button's `aria-label` and `title` (sheets use e.g. `'Close about dialog'`).
4. **Tokens are added, not invented per dialog; no hardcoded spacing/typography in the adopted dialogs.** Add a dialog token block to `:root` (`styles.css:15-491`): `--dlg-pad-x: var(--sp-4)`, `--dlg-pad-y: var(--sp-3)`, `--dlg-gap: var(--sp-3)`, `--dlg-radius: var(--radius-dialog)`, `--dlg-control-h: var(--control-height)`, `--dlg-icon: 16px`, `--dlg-title-fs: var(--fs-lg)`, `--dlg-label-fs: var(--fs-sm)`, `--dlg-help-fs: var(--fs-xs)`, `--dlg-w-sm/Lg/Tool`, `--dlg-max-h`. Rework `.modal-dialog`/`.modal-header`/`.modal-body`/`.modal-footer`/`.modal-input`/`.modal-field` (`styles.css:5841-6045`) to consume these tokens (the current hardcoded `padding: var(--sp-3) var(--sp-4)`, `height: 32px`, `gap: 4px` etc. are replaced by the tokens). Motion stays on the Phase-15 tokens (`--motion-*`); no hardcoded duration/easing/scale.
5. **The content grid is canonical and aligned.** New classes `.dlg-field` (a label + control + help + validation stack), `.dlg-grid` (a two-column label/field grid), `.dlg-label`, `.dlg-help`, `.dlg-error` in `styles.css` next to the dialog block. Labels align on one column, controls on the other, help text wraps under its control, and a validation message occupies the reserved `.dlg-error` slot so a message never shifts the layout (reserve the line, never reflow). `.dlg-input`/`.dlg-select`/`.dlg-textarea` consume `--dlg-control-h`. Adopted dialogs use these classes and must not introduce per-dialog spacing literals. (Post-implementation note, 2026-10-03, TFL-620: the adopted dialogs express the canonical grid through the token-driven `.modal-field` + `.modal-hint` + `.modal-status` stack reworked in Ruling 4; the `.dlg-*` classes above remain the reserved canonical names and are used where an adopter needs a two-column label/field group. The observable requirement - labels/controls/help/error aligned, help wrapping under its control, and a validation message never shifting the layout - is verified by the Phase 92 e2e sweep `e2e/phase92_dialog_shell.spec.cjs`: 74/74 surfaces pass.)
6. **Action hierarchy and placement are fixed.** Exactly one `primary` per dialog action row (right-most), secondary/tertiary to its left, destructive actions use `variant: 'danger'` and sit in the same row (never floating); Cancel is `secondary`; a dialog with a single action renders it as `primary`. Keyboard order follows DOM order; the `default` action receives initial focus; Esc routes to the shell's `onClose`.
7. **Focus and disabled states are preserved and visible.** The shell keeps the existing `--focus-ring` `:focus-visible` behaviour; a disabled action is rendered `disabled` (dimmed, `cursor: not-allowed`) and never focusable-into a no-op; adopters must not remove an existing disabled/`aria-disabled` reason. Accessible names and `aria-labelledby` point at the shell's title id.
8. **Behaviour is preserved exactly; fail-loud parity.** Adoption is structural/visual only: every dialog keeps its open/close wiring, its callbacks, its async/busy gates, its `data-*` hooks, its disabled logic and its content. No control becomes a no-op. Duplicated Esc/focus/backdrop effects are removed only where the shell now owns them.
9. **Auxiliary windows.** `PrintWindowApp.tsx` adopts the shared tokens and control heights for its header/panel typography and spacing (it is a window surface, not a modal, so it does NOT use `DialogShell`); its `data-print-window*` hooks are preserved. The detached document window shares the App renderer, so it inherits the token/shell CSS automatically; no main-process change.
10. **CONTROL-INDEX for a chrome phase.** This phase adds no new app action. Its "controls" are the `DialogShell` contract, the size modifiers and the canonical grid/tokens. qa's sweep opens every adopted dialog and asserts each still exposes its existing root `data-*` hook, its existing confirm/cancel hooks fire, and the shell classes/structure are present.
