## Phase 103 - Quiet Precision shared icon system: one semantic registry + one shared icon component applied app-wide (phase issue TFL-824; operator driver TFL-808, 2026-10-05)

**Operator request (product terms, TFL-808 / phase issue TFL-824).** Replace TFlex's
ad-hoc icon usage with the committed Quiet Precision icon system: one semantic icon
registry keyed by the existing command IDs plus one shared icon component, graphite
resting glyphs, one violet active/selected treatment, green reserved for real success,
red only on verified destructive commands, and a consistent 24 x 24 / 1.65-unit
rounded-outline family built from the 58 supplied original concept SVGs. No command ID,
click handler, shortcut, automation hook, test selector or PDF behaviour changes. This
is visual overhaul 1 of 4; Icons is foundational and must leave one registry the later
Dock (TFL-809), Panels (TFL-810) and Buttons (TFL-812) overhauls inherit.

**CTO RULINGS:**

1. **Scope.** Renderer only: `src/renderer/**` (the new registry/component, every icon
   call site, scoped icon-token CSS) plus renderer unit tests under
   `test/unit/renderer/**`. No IPC/preload/shared-contract change; no `src/main/**`. qa
   owns `e2e/**`, `screenshots/**`, `test-fixtures/**`. No new dependency, no network
   call, no font or icon CDN.
2. **One registry, one component - single source of truth.** The new semantic registry,
   keyed by the existing `toolsRegistry.ts` command IDs plus the chrome/affordance IDs
   (close, minimize, maximize, chevrons, directional arrows and similar), becomes the
   ONLY icon source; the shared component renders every tool/chrome glyph from it. A
   second icon system may not be forked, and Dock/Panels/Buttons later consume this one.
   The registry centralizes `viewBox="0 0 24 24"`, the 1.65-unit rounded stroke, no
   fill, `currentColor`, the 16/20/22/24 optical sizes and the small-size (1.8 at 16 px)
   variant rule.
3. **Use the supplied assets where semantics fit; extend the same grammar for the
   rest.** Build registry entries from the 58 supplied concept SVGs (refined only where
   small-size inspection exposes a problem), author missing glyphs to the identical
   geometry (24 x 24, 1.65, round caps/joins, no fill, currentColor), and where a lucide
   glyph is retained it is normalized to the same view box, weight, caps, joins and
   optical size - never a visibly different family. The brand mark is preserved and a
   brand redesign stays out of scope.
4. **Inventory before replacement.** Before any migration, record every icon across
   navigation, title bar, document tabs, all workspace docks, inspectors, menus,
   dialogs, command palette, empty states, notices and window chrome: command ID,
   current source, contexts, size, label, shortcut, states, intended metaphor and target
   asset. Resolve the ambiguous controls by inspecting handlers (the title-bar save
   variants, the command-symbol action, the dock trailing pencil, sanitization), never
   by guessing; audit icons absent from the supplied screenshots rather than assuming
   coverage.
5. **State and colour discipline.** Ordinary resting icons are graphite in every
   workspace; active/selected uses the single violet treatment; the permanent
   per-workspace purple/green/red category colouring is removed. Green only for a real
   completed/success outcome; red only on genuinely destructive commands (Delete pages
   keeps red at rest). Specialist and format-related commands keep explicit labels. If
   an existing theme definition conflicts, add a scoped icon-token mapping rather than
   replacing the whole theme. Colour is never the only signal; keyboard focus keeps a
   distinct ring; reduced motion is respected and no glyph geometry is animated.
6. **Semantic grammar.** plus for insert/create; outgoing arrow for export/extract;
   incoming arrow for import; converging paths for merge; separated page/frame shapes
   for split; circular arrow for rotation; comment bubble for review; page-check for
   validation; shield for sanitization; padlock for encryption; scan frame with T for
   OCR; Flatten visually distinct from Layers and Crop from Fit-page. The same command
   reuses the same glyph in every context.
7. **No behaviour change.** The registry/component change must not alter any click
   handler, command ID, shortcut, automation hook, test selector, PDF processing, tab
   state or window control. The Phase 43/94 guards are updated to the new source of
   truth (registry plus component) and must still fail on an un-allow-listed shared
   glyph, an ad-hoc inline tool SVG, or a raw numeric icon size.
8. **Tests + evidence.** `npm run typecheck`; the updated and added renderer unit tests
   (registry completeness, geometry tokens, guard suite) actually RUN and green; a build
   check (`npm run build:renderer`) because bundling of the family changes. A
   CONTROL-INDEX lists every control/surface the phase changes with its promised action;
   qa captures representative before/after screenshots in Pages, Edit, Review, Deliver,
   the welcome screen and at least one menu/dialog containing icons absent from the
   supplied references. The full suite is NOT run by default.
9. **Validation performed.** 16/20/22/24 px in light and dark at 100/125/150/200%
   Windows scaling; optical centring, no clipping, clear arrowheads, distinct
   silhouettes; hover/active/disabled/danger/focus; keyboard focus; non-text indicators
   >= 3:1 and normal labels >= 4.5:1 against final backgrounds; disabled icons do not
   react as available controls.
10. **Standard flow + commit.** CTO brief -> frontend-dev (renderer) -> qa FIX-READY and
    visual verification -> adversary diff-pass -> phase-close QA verdict -> ONE local
    phase-close commit via git-agent. No push, no tag, no release and no credential
    change without explicit operator approval.
