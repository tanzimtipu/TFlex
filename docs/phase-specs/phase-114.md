## Phase 114 - Preferences and Themes overhaul: the Settings Studio (phase issue TFL-1219; CEO commission, 2026-10-08)

**Operator request (product terms, TFL-1219 / category handoff `Visual overhaul/Preferences and Themes/`).** Replace the current Preferences and Themes surface with one consistent, truthful **Settings Studio**: a short section navigator over readable settings groups, using the four real categories the installed app exposes - **General, Documents, Import & conversion, Storage** - not the prototype's schematic Appearance / Workspace. Every appearance and preference entry point stays in one store and one renderer. Actual current values, per-setting application timing and persistence feedback are shown. Precedence: live-app refinements > design-decisions > illustrative visuals; consistency corrections and the unified semantic tokens remain in force. Out of scope: network features (offline-first); new density/layout controls (separately scoped proposals).

**CTO rulings:**

1. **Scope.** Renderer only: `src/renderer/components/PreferencesDialog.tsx`, a new Settings Studio primitive module under `src/renderer/components/`, the preferences sections of `src/renderer/styles.css`, the host wiring in `src/renderer/App.tsx` (the `<PreferencesDialog>` props and its setters only), renderer unit tests, and the inventory document under `docs/`. No `src/main/**` change is expected; no `src/shared/**` change; no new IPC; no new `AppSettings` field; no new dependency; no network call. qa owns `e2e/**`, `screenshots/**`, `test-fixtures/**`. If the inventory proves a main-process default/reset helper is unavoidable, it must reuse the existing `settings:save` channel and add no field - and the CTO must re-rule before it is built.
2. **One surface, no forks.** Migrate every entry point onto the single Settings Studio. Reuse the shipped primitives - `DialogShell` (surface="sheet"), `Button`/`IconButton`, `Icon`, `TfResize`, the Phase 100 `src/renderer/design` tokens - and the existing command/menu/dialog/operation systems. Do not introduce a parallel store, a second preferences reducer, or per-call-site CSS overrides. The header theme control (Top Bar and Tabs) and Home decorative motion (Home Screen) keep their owning surfaces; the Studio coordinates with them, never reimplements them.
3. **Inventory before migration.** Record every real entry point, its command ID, handler, capability predicate, backing `AppSettings`/document-store field, scope, application timing (immediate / next launch / next import / next session) and persistence path, and whether it is supported, needs a capability-backed extension, or is unsupported. Resolve each setting's application model from the live code, never by guessing.
4. **Truthfulness gated.** Render only settings the app supports; preserve existing IDs, values, scope and application timing. No invented Apply/Cancel footer on settings that already apply immediately - use Close plus persistence feedback and per-setting timing help. Theme default stays the existing **Frosted**; every existing theme is retained; **System** stays (the app observes and persists it via `resolveThemeDefault`/`themeDefault`). No new density/layout control.
5. **Theme and pixels.** Apply the light/dark semantic tokens to Studio surfaces and controls only; never recolor PDF page pixels or alter document content by configuring a preference. Document-tab identities stay colorful and stable across themes with contrasting selected text.
6. **High contrast.** Forced-colors / high-contrast overrides ornamental fills while keeping filenames, states and visible focus; provide a truthful fallback where translucent materials are unsupported; no glass beneath dense settings text.
7. **Motion.** Keep the global **Animations** preference; OS reduced motion always wins (an enabled preference never overrides it). Home's decorative motion stays wired through the same `motionPolicy`/`useOrbitMotion` intersection; the paused state persists between visits; never animate the brand logo or document pixels.
8. **Truthful subsystems.** Storage stays a **locations browser** (user-data, settings, saved-signature locations) - no invented cache metrics or cleanup actions. Documents exposes the Windows default-PDF-app handoff. Import & conversion defaults (A4, 20 mm margin, Inter, 11 pt, delimiter Auto-detect, CSV column mapping, HTML backgrounds) apply to the next import.
9. **Failure and defaults.** A persistence failure restores the prior value in the UI and shows an actionable error (the backend already rolls back and emits `settings:writeError`; the renderer must not keep showing the unpersisted value). **Restore defaults** is a capability-backed extension: it states its scope in the UI and restores settings only - never documents, document history, saved signatures or other user assets; sensitive preferences retain their existing explicit security controls.
