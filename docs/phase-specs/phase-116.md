## Phase 116 - Comments and Review overhaul: Thread Stream (phase issue TFL-1228; CEO commission from TFL-1221, 2026-10-08)

**Operator request (product terms, TFL-1228 / category handoff `Visual overhaul/Comments and Review/`).** Give Comments and Review one consistent, truthful **Thread Stream** surface so every annotation and review entry point is readable, theme-aware, accessible and honest about what the app can do. One Thread Stream carries real annotations and real replies only where the engine supports them; the **left navigator** owns annotation navigation and filtering; the **right inspector** owns the selected annotation's editable properties and shows document properties when nothing is selected; a **floating editor** is for the current draft and nearby contextual controls, never a third duplicate comments list; **Page Ledger** is the layout alternative and must reuse the same state and handlers. Truthfulness gates acceptance: render only real PDF annotation / supported-engine metadata; never invent collaborators, people, timestamps, unread counts or cloud synchronization; show an annotation's real author only when one exists, otherwise a neutral annotation glyph (no fabricated initials); quote selected text only when it is reliably associated with the annotation, otherwise label its actual type; long comments wrap and expose full content; threaded replies, authors and Resolve / Reopen are capability-dependent and ship only when backed by real state plus save / export behavior (an empty bundled sample establishes neither availability nor absence); FDF comment import / export reuses the existing handlers, surfaces format / compatibility limits and partial / failed imports, keeps imported author / date as source data (not identity claims), preserves native annotation IDs / relationships and avoids duplicate annotations on retry; document permissions, signatures and read-only documents govern every mutation; a filter must not erase an unsent reply or the selected annotation, and an empty document must be distinguished from an empty filtered result with one explanation and a meaningful supported action; delete affects the intended annotation under the existing confirmation / undo policy; multi-select exposes Mixed and deliberately scoped changes; selecting a view, filtering or configuring options never recolors PDF pixels or alters document content. Precedence: live-app refinements > design-decisions > illustrative visuals; Consistency Corrections and the unified semantic tokens stay in force. Out of scope: any network / mail / cloud collaboration; any recolor of PDF pixels.

9. **Seams reconciled, never duplicated.** Selection and Manipulation / Inspector First (TFL-1222) and the Panels Context Pair primitives own the inspector chrome - reuse. Drag Drop and Import (TFL-1223) owns general intake - comment FDF stays in the Review list-level actions. Forms and Validation / Guided Fill (TFL-1227) owns form values - comment / form-data boundaries stay distinct. Print and Output / Output Studio (TFL-1225) shares the Bates / watermark / signature sections - render once, coordinate. Responsive and Accessibility / Adaptive Shell (TFL-1224) owns global responsive / accessibility rules - apply, do not fork. Dialogs, Toolboxes and Menus owns modal mechanics - reuse for delete / import confirmations. Design System / Consistency Corrections stay in force, including item 7 (one comment list on one navigation surface).
10. **Accessibility, adaptation and pixels.** Labels, transient focus / Escape, screen-reader names, forced-colors / high contrast, reduced motion, resize / theme adaptation, long / localized labels and 200% scaling are implemented; controls stay above page content and clear of the dock and viewing footer. Selecting an annotation, filtering or configuring a view never recolors a PDF pixel or changes document content, and UI tokens never replace PDF fonts. Preserve command IDs, session identity, undo / draft semantics, keyboard bindings, permissions and native Windows chrome.
