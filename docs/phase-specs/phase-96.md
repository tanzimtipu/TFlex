## Phase 96 - App-wide modern visual design refresh: one deliberate colour system, elevation, and designed empty states (operator request TFL-499 / phase TFL-510, 2026-10-04)

**Operator request (product terms, TFL-499 / TFL-510):** the app reads as bare-bone - flat, low-contrast chrome, little deliberate colour and almost no graphical identity. Apply one modern, cohesive visual design across the **whole** app (home/start, library, viewer, editor, toolbars, docks, sidebars, panels, menus and dialogs), not only the home screen. The result must look visibly modern beside Acrobat, Foxit and PDF-XChange without copying any of them. Offline only; no network feature.

**Relationship to the shipped design-token layer and the completed renderer phases (13/14.1/15/38/40/41/51/58/59/91/92/93/94/95).** A real token layer already exists in `src/renderer/styles.css`: the `:root` block (`:15-597`), the dark block (`:root[data-theme="dark"]`, `:599-735`) and the frosted block (`:root[data-theme="frosted"]`, `:764-964`) define type, spacing, radii, control sizes, motion, the accent ladder, surfaces, text, borders, semantic states and shadows; Phase 91 added the button token block and taxonomy (`docs/BUTTON-SYSTEM.md`), Phase 92 the dialog shell/tokens, Phase 94 the icon system (`src/renderer/icons/Icon.tsx`, `--tf-icon-*`), Phase 95 the dock containment. Phase 96 is the **app-wide colour + depth + empty-state layer** those phases explicitly deferred: Phase 91 Ruling 4 states the colour-refresh phase "owns colour" and that it "moves one value and every destructive hover follows"; Phase 94 Ruling-relationship states the visual refresh "consumes this result and must not redo icons". Phase 96 therefore **owns the colour/elevation/empty-state system and NOTHING structural**: it does not restyle buttons (Phase 91), dialog structure (Phase 92), Book View motion (Phase 93), icon artwork/glyphs (Phase 94), or dock geometry/hit-boxes (Phase 95). No `src/main/`, no `src/shared/`, no `src/preload/`, no IPC, no `package.json`/dependency change, no settings field, no new document model, no network call.

**CTO RULINGS:**

1. **Scope and files.** Renderer only. The colour/elevation system lives ONCE in `src/renderer/styles.css`: the `:root` block (`:15-597`), the dark block (`:599-735`), the frosted block (`:764-964`), and the surface/state/shadow rules across the file. New: `docs/DESIGN-SYSTEM.md` (the colour + elevation + empty-state spec) and its contract test `test/unit/renderer/designSystem.test.ts`; a shared `src/renderer/components/EmptyState.tsx` **only if** more than one surface needs it (plus `test/unit/renderer/emptyState.test.tsx`); an allowed addition: `e2e/phase96_design_system.spec.cjs`. No `src/main/`, `src/shared/`, `src/preload/`, no `package.json`/dependency change, no IPC, no settings field. If frontend-dev finds a surface it cannot retune without a structural/behaviour change, it stops and reports rather than widening scope.
2. **One documented colour system is the single source of truth.** `docs/DESIGN-SYSTEM.md` documents every token family the app paints with - brand/accent (`--accent`/`-hover`/`-pressed`/`-soft`/`-text`, `--sem-primary`), surfaces (`--bg-base/sunken/raised/toolbar/rail/canvas/input/menu/secondary/elevated/panel`, `--panel-bg`, `--glass-*`), the text ladder (`--fg-strong/fg/soft/muted/faint/disabled/on-accent/on-page`), borders/dividers (`--border/-strong/-subtle`, `--divider`), semantic state (`--info/success/warning/error` + `-soft`), the four-role palette (`--sem-neutral/affirmative/attention`), and interaction/selection tokens - for all three themes, each with its value, its purpose and its measured contrast. The doc is not allowed to drift from the shipped CSS: `designSystem.test.ts` reads `styles.css` and pins that every documented token exists in each theme scope with the documented role (mirror `buttonTaxonomyContract.test.ts`).
3. **The brand hue is fixed; the stale docs are the bug.** `#7C3AED` stays the one accent in light/frosted and `#A78BFA` remains the dark counterpart; Phase 96 does not introduce a new brand hue. It MUST correct every stale/contradictory colour comment so the file, the docs and the tokens agree (the four `#2563eb` comment occurrences at `:2`, `:75`, `:470`, `:2535`, and the "no purple" header line must be rewritten to state the violet brand). Any orphan hue literal not derived from a token and painted on a named surface is replaced by a token.
4. **Contrast is contract, not aspiration.** Every interactive-text pair is >= 4.5:1 and every icon/graphic/edge pair is >= 3:1 in light, dark AND frosted. The existing measured oracles (`phase38LegibilityContrast.test.ts`, `phase40SemanticPalette.test.ts`, `designTokensContract.test.ts`) MUST stay green after any retune; where a token value moves, its consumers move with it and the oracle proves the composite. No new low-contrast one-off.
5. **A documented elevation ladder.** Add one elevation scale - `--elevation-1/2/3` (or a documented mapping onto the existing `--shadow-*` family, whichever is less churn) - with a fixed surface->depth contract: chrome/toolbar/rail = flat, panel/card/selected-group = level 1, popover/menu/flyout = level 2, dialog/sheet = level 3, toast/floating chip = level 4. Depth is visible but restrained in light and dark (no heavy black slabs, no blue cast). Named surfaces consume the ladder; ad-hoc `box-shadow` literals on named surfaces are removed in favour of it. The ladder and its mapping are documented and pinned by `designSystem.test.ts`.
6. **Designed empty states, not default text.** Every surface that can be empty gets a designed empty state: a single `Icon` mark at the Phase-94 `hero` size (`--tf-icon-size-hero`, 32px) in a token-driven tint, one headline line and one help line, on the token surface with the level-1 elevation. Named surfaces: Welcome recent-files (`.recent-empty`, `Welcome.tsx:434-443`), Welcome samples (`.samples-empty`, `:485-497`), the Inspector/ContextPanel no-selection state, the search no-results state, and the thumbnail rail when a document has zero pages. The empty-state pattern (mark/headline/help surface treatment) is documented in `docs/DESIGN-SYSTEM.md`; a single shared `EmptyState` component is used where two or more surfaces share the pattern. Copy is English, no emoji, one short sentence per line.
7. **Interaction states are coherent on non-button surfaces.** Hover, active, focus, disabled and selected on rows, list items, cards, tabs, menu rows, panel headers and on-canvas overlay controls consume the shared state tokens (`--bg-hover`, `--bg-active`, `--accent-selected`, `--select-fill`/`--select-edge`/`--select-glyph`, `--focus-ring`) - never a per-surface alpha literal. Button variants and their states are Phase 91's and must NOT be re-tuned; only the colour tokens a button consumes may move (Ruling 2), and Phase 91's `buttonTaxonomyContract.test.ts` plus `docs/BUTTON-SYSTEM.md` stay green.
8. **Light and dark are equally designed; frosted derives from the same system.** Every new or changed token is defined in all three scopes. Chosen defaults: neither theme is an afterthought; the flat light theme gets real surface separation and depth, the dark theme keeps its near-black canvas with a legible chrome ramp, and frosted stays a neutral light acrylic over the same system. The PDF page/canvas stays opaque and paper-white in every theme (DEF-099); only chrome is translucent.
9. **No regression, fail-loud parity.** Functionality, layout structure, control geometry/hit-targets, every `data-*` e2e hook, keyboard behaviour, copy (except the specified empty-state strings) and every existing test are preserved. This is a visual token/system phase: it must not move a control, change an action, or turn anything into a no-op. Main process, engine, PDF rendering/zoom, save/export, undo/redo, printing and settings are untouched.
10. **CONTROL-INDEX for a visual system phase.** This phase adds no new app action and no new window. The "controls" it introduces are the token contract and, where used, the `EmptyState` component contract (mark + headline + help). qa's sweep opens each named surface in light, dark and frosted, asserts the shipped action and every existing `data-*` hook still work (no-op sweep), asserts the empty state renders where a bulk surface can be empty, and checks the contrast floors.
11. **Settings impact:** none. No new persisted `AppSettings` field, no change to any existing settings shape, no new settings channel and no credential. Renderer-only, offline; no network call is added.
