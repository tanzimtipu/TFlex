## Phase 89 - Bates numbering (FEA-033, commissioned via TFL-315 / TFL-464, 2026-10-03)

**Operator request (product terms, TFL-464):** let a user configure a **prefix**, **suffix**, **start number**, **digit padding** and **page position**, then **apply sequential Bates numbers to the selected pages** of the active document, producing a **real saved page overlay** of the stamp text that survives save/reload. Legal and accounting workflows expect Bates stamps; plain page numbering does not cover them. Offline only; no network feature.

**Relationship to Phase 18 (watermark), Phase 12 (text stamp palette) and the save path.** Bates numbering is the same *kind* of operation as the shipped Phase 18 watermark: it bakes text into each selected page's content stream as **real glyph-show operators**, undoable through the per-document queue and persisting across save/reopen. This phase mirrors that proven path (`_addWatermarkImpl`, `engine.ts:3947`; marker `WATERMARK_MARKER_PREFIX`, `engine.ts:246`; content-stream emission `engine.ts:4177-4231`) and uses a distinct `%TFLEX-BATES ` marker so the two features stay independently addressable. It adds one pure shared module, the shared contract, one engine op / one IPC channel, the preload/main wiring, one persisted settings field and one renderer dialog. It adds no window, no new document model, no second settings channel and no network. The app has **no header/footer or page-number feature** (FEA-002 is still PROPOSED), so the only shared machinery at risk is the Phase 18 watermark bake and the Phase 12 stamp palette; neither is modified for its own behaviour.

**Capability boundary (honest, non-negotiable).** pdf-lib cannot reuse an embedded subset font, so the Bates label is drawn in a **StandardFont substitution** from the existing edit-font allowlist (`isEditFont`; default `AppSettings.editDefaultFont`, else `Helvetica`). The composed label is the user prefix + zero-padded number + user suffix; a prefix/suffix character the chosen standard font cannot encode **rejects the whole payload with a readable `engine-error`** naming the cause - it is never dropped or transliterated silently. The stamp is written as real page content, so it is visible in other readers, present in text extraction and survives save/reload; it is **not** an annotation object.

**CTO RULINGS:**

1. **Scope is one new pure shared module, the shared contract, the main-process engine op + preload/main wiring, one persisted settings field, and one renderer dialog.** Files: `src/shared/bates.ts` (new, pure), `src/shared/types.ts` and `src/shared/ipc.ts` (contract), `src/main/services/engine.ts` (the op), `src/main/index.ts` (handler), `src/preload/preload.ts` (bridge), `src/main/services/settings.ts` (the field), new `src/renderer/components/BatesDialog.tsx`, `src/renderer/state/toolsRegistry.ts`, `src/renderer/App.tsx` and `src/renderer/engine/{engineClient,types,stubEngine}.ts`. No new window, no new document model, no second settings channel, no network.
2. **One shared, pure source of truth for the label string and the series.** New `src/shared/bates.ts`, pure (no `fs`, no Electron, no DOM, no pdf-lib), mirroring `src/shared/blankPages.ts` / `sanitize.ts` discipline. It exports `buildBatesLabel(prefix: string, number: number, padding: number, suffix: string): string` returning `${prefix}${String(number).padStart(padding, '0')}${suffix}`; `formatBatesSeries(settings: BatesSettings): string[]` returning one label per selected page in selection order (`startNumber + k` for the k-th page); `DEFAULT_BATES_DEFAULTS`; and `normalizeBatesDefaults(raw: unknown): BatesDefaults` (preserve-if-valid per key, missing/invalid -> default). Every function is unit-tested directly, with no PDF.
3. **One new engine op and one new IPC channel.** `engine.addBates(docId, settings)` on channel `engine:addBates`. `BatesSettings { pages: number[]; prefix: string; suffix: string; startNumber: number; padding: number; position: WatermarkPosition; font?: EditFont; size?: number; color?: EditColor }` where each `pages` entry is a 1-based VISIBLE page and the array order is the numbering order. It returns `Result<BatesResult, EngineError>` where `BatesResult { state: EngineState; stamped: number[]; labels: string[] }` (`stamped` and `labels` parallel, in numbering order). The op validates the whole payload first and is **all-or-nothing**: an empty `pages` list is the typed `empty-range`; any non-integer, out-of-range or duplicate entry, an invalid `startNumber`/`padding`/`font`/`position`, or a label the chosen standard font cannot encode is a typed error (`out-of-range` / `engine-error`) and the document is left byte-for-byte unchanged. On success it takes exactly ONE `snapshotDocWithPdf` before any mutation (so a Bates run is one undo entry), bakes one dedicated content stream per selected page exactly as Ruling 5 describes, pushes the snapshot, sets `doc.modified = true`, and is enqueued through `_enqueue` like every other mutating op.
4. **Numbering and padding.** The k-th page in `pages` (0-based k) receives number `startNumber + k` and label `buildBatesLabel(prefix, startNumber + k, padding, suffix)`. `padding` is the minimum digit width, zero-filled (`padding: 6` -> `000001`). Only the listed pages are stamped; every other page is byte-for-byte untouched. Pages may be listed in any order; the numbering follows the list order, so the renderer offers document order by default.
5. **The stamp is real page content with an identity marker.** Each stamped page gets one new uncompressed content stream whose first line is `%TFLEX-BATES ` + base64url JSON `{ id, page, label }` (mirroring the `%TFLEX-WATERMARK ` marker), followed by `q / GS / BT ... ET / Q` operators (font, size, fill colour, `setTextMatrix`, `showText(font.encodeText(label))`) positioned by the shared 3x3 slot maths. The marker is the single source of truth for "this page was stamped" and makes "only the selected pages were stamped" directly verifiable; this phase does **not** add list/delete ops for Bates markers.
6. **Font, size and colour are validated, not guessed.** The op embeds `settings.font ?? AppSettings.editDefaultFont ?? 'Helvetica'` via the existing `embedEditFont` and validates it with `isEditFont`. `size` is a finite number in `MIN_BATES_SIZE..MAX_BATES_SIZE` (default `DEFAULT_BATES_SIZE = 10`); `color` is an `EditColor` with each component in `[0,1]` (default black). Before any mutation the op encodes the widest composed label with the chosen font; if the encoding would drop characters the whole payload is refused with a readable `engine-error` naming the offending input - a non-Latin prefix/suffix is a loud refusal, never a silent mangle.
7. **Position is the shared 3x3 slot.** Reuse `WatermarkPosition` with the same 10%-page-margin centre convention; default `'bottom-right'` (the Bates convention). No tiling, no explicit x/y override and no rotation are in scope.
8. **Fail-loud, never a silent skip.** An empty list, an out-of-range/duplicate/non-integer page, an invalid option, an unencodable label or a page that cannot be resolved refuses the **whole** op with a typed error and mutates nothing; the dialog shows the error in `[data-bates-report]`. There is no partial-success path that quietly omits a selected page.
9. **The Bates defaults are a persisted setting.** `AppSettings.batesDefaults?: BatesDefaults` with `BatesDefaults { prefix: string; suffix: string; startNumber: number; padding: number; position: WatermarkPosition }`, default `DEFAULT_BATES_DEFAULTS = { prefix: '', suffix: '', startNumber: 1, padding: 6, position: 'bottom-right' }`. It is validated preserve-if-valid per key in `src/main/services/settings.ts` `normalizeSettings` (the main-process normaliser that runs before any renderer reads the value) and transported over the existing AppSettings IPC. The dialog reads it for its initial values and writes it back on apply. No new settings channel and no credential.
10. **No regression** to the Phase 18 watermark (its marker scan, apply, get and delete), the Phase 12 text stamp palette, page rendering/zoom, save/export, undo/redo or settings persistence. The feature is fully offline (no network call, nothing leaves the machine).
