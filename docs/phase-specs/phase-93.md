**Root cause (verified by reading the shipped code).**

1. The turning leaf mounts a fresh `BookPage` -> `PageView` for each face on every turn (`BookView.tsx:399-445`). A freshly mounted `PageView` has no previous frame, fills opaque white, and only paints the PDF bitmap asynchronously (`PageView.tsx:443-683, 693-702`), so the OUTGOING face - the page that should be on screen the instant the turn starts - flashes blank, and the INCOMING face is blank for the first part of the swing. This is the primary flicker.
2. `stepForward`/`stepBack` advance `pageIndex` in the SAME commit that starts the leaf (`BookView.tsx:298-309`). The static spread underneath therefore swaps to the destination immediately: in a double spread the non-turning half jumps, and the turning half's slot keeps the OUTGOING page's bitmap until the new page paints (`PageView.tsx` keep-previous-frame path), so at turn end, or on a slow render, the book can show a stale/incorrect page or a stacked ghost layer.
3. Each leaf `BookPage` starts from the placeholder `INITIAL_PAGE_DIMS` (`BookView.tsx:81, 162`) and only gets its true page geometry after `onPageSize`, so the leaf's faces reflow/pop one frame in.
4. A turn is one-shot with a 400 ms fallback timer (`BookView.tsx:91, 316-320`); a rapid second turn replaces the leaf `key` and unmounts the old leaf mid-swing, and a coalesced input can snapshot `front`/`back` from a stale `current` closure (`BookView.tsx:287-309`) - leaving ghost layers or the wrong page.
5. Under `prefers-reduced-motion: reduce` or `:root[data-animations="off"]` the layout token collapses to `--motion-duration-reduced` (0 ms) (`animations.css:109-150, 164-173`), but the leaf is still mounted and still overlays a fresh white `PageView`; until the 400 ms fallback clears it the page can look blank or half-applied.

2. **The turning face is the already-painted page - never a fresh repaint.** The visible OUTGOING face during a turn must be the page that was already on screen before the turn began (reuse the mounted `PageView` canvas, or transform the existing static `[data-book-page]` element in place), not a newly mounted `PageView`. The INCOMING page must be painted (its pdf.js render promise resolved) before the swing reveals it past the spine. No face may show the white pre-paint fill on screen, at any moment.
3. **The base spread does not change until the turn settles.** During a turn the static spread stays on the OUTGOING index; the destination index is committed exactly once, on the turn's `animationend` (or synchronously in the same handler with no leaf when motion is instant). At rest the book always shows the committed pages: no stale page, no ghost layer, no mid-flip content jump. The two faces of a spread stay joined at the spine for the whole turn - no gap, no overlap pop.
4. **Rapid input is coalesced.** Repeated clicks must never stack leaves and must never leave `data-book-turning="true"` with no leaf mounted. At most one turn is in flight; extra input during a turn is coalesced into at most one queued step applied from the committed destination. Every leaf clears via its own `animationend`; the fallback timer remains only as the jsdom/no-CSS guarantee.
5. **Instant mode mounts no leaf.** When `prefers-reduced-motion: reduce` or `:root[data-animations="off"]` is active, step and `chooseLayout` skip the leaf entirely and commit the destination synchronously, so there is no half-applied transform and no ghost overlay lingering for the 400 ms fallback. The reduced-motion result must be identical to the settled animated result.
