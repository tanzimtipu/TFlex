## Phase 91 - Modern professional button system across TFlex UI (operator request TFL-501 / parent TFL-499-era "App button improvement", 2026-10-03)

**Operator request (product terms, TFL-501):** the app's buttons look old and inconsistent. The context-panel and inspector-panel buttons in particular are "just text on a plain flat background", with no visible affordance. Replace the plain, text-only look with a modern, professional button system applied consistently across every surface - top bars, toolbars, side and context panels, the inspector, dialogs and menus - and document the button categories as a reusable single source of truth. Offline only; no network feature.

**Relationship to the shipped design tokens (Phases 13/14.1/15/40/58/59), the colour-refresh phase and the icon phase.** A design-token layer already exists (`src/renderer/styles.css` `:root`, lines 15-491: `--accent`/`--accent-hover`/`--accent-pressed`, `--bg-raised`/`--bg-hover`/`--border`/`--fg-strong`/`--fg-muted`/`--fg-on-accent`/`--error`, `--radius-*`/`--radius-control`, `--sp-*`/`--space-control`, `--control-height`, `--focus-ring`, `--shadow-*`), and a base `.btn` family already exists (`.btn` `styles.css:3165`, `.btn-primary` `:3199`, `.btn-danger` `:3271`, `.btn-secondary` `:3285`, plus the shared hover/press group `:12072-12178`). But there is no shared button component (379 raw `<button>` elements, none factored) and the surfaces hand-roll dozens of one-off classes (`.tool-btn`, `.toolbox-action-btn`, `.titlebar-file-btn`, `.rail-action-btn`, `.stage-rail-btn`, `.text-props-btn`, `.context-panel-action`, `.inspector-action`, `.action-dock-verb`, `.home-tool`, ...), which is exactly the inconsistency the operator is reporting. Phase 91 is a **renderer-only consolidation/restyle**: it introduces the missing categories (ghost, icon-only, toolbar, toggle, segmented) on top of the existing tokens, adds the one shared component, documents the taxonomy, and migrates every shipped surface onto it. It does **not** change the colour tokens themselves (the app-wide colour-refresh phase owns colour), does **not** redesign the icon artwork (TFL-479 owns icons) and does **not** renovate dialog/window chrome beyond the button treatment (TFL-481 owns chrome). No main-process code, no `src/shared/`, no IPC, no settings channel, no new document model, no network.

**CTO RULINGS:**

1. **Scope and files.** Renderer only. New: `docs/BUTTON-SYSTEM.md` (the taxonomy), `src/renderer/components/Button.tsx` (exports `Button` + `IconButton`), `test/unit/renderer/buttonSystem.test.tsx` (DOM behaviour), `test/unit/renderer/buttonTaxonomyContract.test.ts` (CSS/token + doc pin). Modified: `src/renderer/styles.css` (button tokens in `:root` and the `.btn` family + shared hover/press group) and the surface components listed in Ruling 6. No other areas. No `src/main/`, no `src/shared/`, no `src/preload/`, no `package.json` dependency changes.
2. **One documented taxonomy is the single source of truth.** `docs/BUTTON-SYSTEM.md` defines every category - **primary, secondary, tertiary/ghost, icon-only, toolbar, destructive, toggle, segmented** - and for each: its purpose and when to use it, its visual treatment, its sizing, its corner radius, its internal spacing, its icon usage, and its five interaction states (default, hover, active/pressed, focus, disabled). Each category names the canonical class(es) and the CSS token(s) it consumes, and shows the exact markup (e.g. `<button class="btn btn-secondary">`, `<button class="btn btn-ghost btn-icon" aria-label="..." title="...">`). The doc is not allowed to drift from the shipped CSS: the taxonomy-contract unit test pins the class names and the token usage so a change that breaks the documented taxonomy fails `npm run test:unit`.
3. **`.btn` stays the base namespace; add variants, do not fork a parallel one.** Keep `.btn` as the base and upgrade it to the modern treatment (height from `--btn-h` (default `--control-height`), radius from `--btn-radius` (default `--radius-control`), internal spacing from `--sp-*`, motion from the `--motion-*` tokens). Variants to exist and be fully stated:
   - `.btn-primary` (accent fill, `--fg-on-accent` text) - existing.
   - `.btn-secondary` (raised surface `--bg-raised` + `--border`) - existing.
   - `.btn-ghost` (**new**) - transparent fill and border at rest, `--bg-hover` fill on hover, `--accent-pressed-soft` on active; the default for low-emphasis/tertiary actions.
   - `.btn-danger` (destructive) - existing, refined to consume a new `--error-hover` token.
   - `.btn-icon` (**new**) - square icon-only: width equals the variant height, zero gap, glyph centred; never renders a text label; requires an accessible name.
   - `.btn-toolbar` (**new**) - compact square toolbar variant sized by `--btn-toolbar-size` (default `--btn-h-sm`), for the command bar, annotation toolbar and in-canvas overlay toolbars.
   - `.btn-toggle` (**new**) - neutral at rest; selected state driven by `[aria-pressed="true"]` (accent-soft fill + accent border), not by a per-surface `-active` class.
   - `.btn-sm` (**new**) - a size modifier; and the **segmented** group: `.btn-segmented` (container, `role="group"`) + `.btn-segmented-item` (item), where only the outer group corners take `--btn-radius` and the selected item uses the `.btn-toggle` treatment.
   Every variant defines all five states explicitly; disabled uses `[disabled]` (and `aria-disabled` where the native attribute cannot be set) with a visible dim and `cursor: not-allowed`, never colour alone.
4. **Additionally, add the missing tokens; reuse everything else.** Add a small button token block to `:root`: `--btn-h` (default `--control-height`), `--btn-h-sm`, `--btn-toolbar-size`, `--btn-icon-size`, `--btn-radius` (default `--radius-control`), `--btn-gap` (default `--sp-2`), and the missing `--error-hover` (there is none today - `.btn-danger:hover` uses a fallback literal, `styles.css:3277`). Every state transition and press uses the Phase-15 motion tokens (`--motion-duration-fast`, `--motion-ease-standard`, `--motion-scale-press`); **no hardcoded duration, easing or scale** (Phase 15 rule, AGENTS.md). No new colour values are introduced - colour comes only from the existing tokens so the later colour-refresh phase can move them in one place.
5. **One shared component: `Button` and `IconButton` in `src/renderer/components/Button.tsx`.** Both are thin, stateless class-composers (no behaviour wrapper) that forward every native prop and every `data-*` attribute unchanged, so all existing e2e hooks and `onClick`/`disabled`/`type`/`ref` semantics survive verbatim.
   - `Button`: `variant?: 'primary' | 'secondary' | 'ghost' | 'danger'` (default `'secondary'`), `size?: 'md' | 'sm'` (default `'md'`), optional `icon`, children as the label.
   - `IconButton`: `label: string` (**required**; sets both `aria-label` and `title` so the tooltip contract cannot be forgotten), `variant?: 'ghost' | 'secondary' | 'danger' | 'toolbar' | 'toggle'` (default `'ghost'`), `size?: 'md' | 'sm'`, `pressed?: boolean` (renders `aria-pressed` for the toggle category), optional `icon`.
   The component mirrors the prop-interface + className/data-* conventions of `AnimatedDialog.tsx:23-40` and `ConfirmDialog.tsx:26-38` (the latter's `data-confirm-dialog-action` buttons at `:118-129` are the canonical `.btn` usage the component must stay compatible with).

The surface groups:

   - **Panels / rails / docks:** `ActionDock.tsx`, `MultiActionDock.tsx`, `StageRail.tsx`, `SideRail.tsx`, `ContextPanel.tsx`, `Inspector.tsx`, `ToolsPalette.tsx`, `AnnotationFlyout.tsx` - the surfaces the operator explicitly called out.

   Legacy classes to retire or alias: `.tool-btn` (+`-active`/`-optimize`/`-audit`/`-form`), `.toolbox-action-btn` (+`--confirm`/`--cancel`/`--delete`), `.sig-action-btn*`, `.content-action-btn`, `.edit-box-toolbar-btn*`, `.edit-image-toolbar-btn*`, `.ann-textbox-action-btn`, `.titlebar-file-btn` (+state suffixes), `.rail-action-btn`, `.rail-tab`, `.stage-rail-btn`, `.text-props-btn`/`.text-props-wide-btn`/`.text-props-mini-btn`, `.context-panel-action`, `.context-panel-combine`, `.inspector-action`, `.inspector-link`, `.outline-link`, `.tools-palette-close`, `.action-dock-verb`/`.action-dock-more`/`.action-dock-plus`/`.action-dock-edit`/`.action-dock-minus`/`.action-dock-menu-item`, `.home-tool`/`.home-tools-*`, `.recent-row-open`/`.recent-row-remove`, `.sample-card`, `.command-palette-row`. Toggle-shaped legacy classes migrate to `.btn-toggle` with `aria-pressed`.
7. **Accessibility contract (enforced, not aspirational).** Icon-only buttons use `IconButton`, so they always carry `aria-label` + `title`. Keyboard focus is always visible through `--focus-ring` on `:focus-visible` for every variant. Text and icon contrast clears WCAG AA (4.5:1 for label text) in light, dark and frosted; primary/danger use `--fg-on-accent`/white. Toggle state is exposed as `aria-pressed`; a segmented group is `role="group"` with a group `aria-label`. Disabled controls are non-interactive and dimmed. No surface may override a canonical variant's colour/state styling - only size (`btn-sm`) and layout (alignment/min-width) are surface-local.
8. **No regression and fail-loud parity.** Every button keeps its existing action, disabled logic, keyboard shortcut and every `data-*` e2e hook; the migration is visual only and must not turn any control into a no-op. Unaffected: main process, engine, PDF rendering/zoom, save/export, undo/redo, settings persistence, printing. No network call or credential is added anywhere.
9. **CONTROL-INDEX for a restyle phase.** This phase adds no new app action, so the index lists the canonical **classes and component contract** it introduces (`Button`/`IconButton`, `.btn-primary`/`.btn-secondary`/`.btn-ghost`/`.btn-danger`/`.btn-icon`/`.btn-toolbar`/`.btn-toggle`/`.btn-sm`/`.btn-segmented`) and the surfaces it migrates. qa's no-op sweep clicks a representative control per surface group and asserts each still performs its shipped action and still exposes its existing `data-*` hook.
