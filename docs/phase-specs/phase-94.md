## Phase 94 - Modern professional icon system: one cohesive, tokenized, theme-aware vector set across the whole UI (operator request via parent TFL-479 / driver TFL-527, 2026-10-03)

**Operator request (product terms, TFL-527):** Replace the app's entire user-visible icon set with a modern, rich, professionally designed system so Jovrel reads as a current, polished product instead of a legacy tool. Every icon a user can see - toolbar, menus and context menus, side panels, dialogs, status bar, tabs, empty/home states and in-app controls - must be rebuilt/replaced with modern iconography that is visually consistent (one stroke weight, corner treatment, grid and metaphor style), crisp at every rendered size, thematically aware (light and dark) and offline (bundled; no runtime network fetch). Icons that look old, skeuomorphic or inherited from legacy applications must not remain anywhere in the UI. Functional/behavioural changes to controls are out of scope: this is a visual icon overhaul only.

**Relationship to TFL-510 and to the sibling in-flight renderer phases (91/92/93).** TFL-527 owns the icon set; the app-wide visual refresh [TFL-510] consumes this result and must not redo icons (CEO coordination note on [TFL-527](/TFL/issues/TFL-527)). This phase is renderer-only and app-wide. Phase 91 owns the button taxonomy, Phase 92 the dialog shell and Phase 93 Book View motion - Phase 94 must not restyle buttons, change dialog structure or touch motion. No `src/main/`, no `src/shared/`, no `src/preload/`, no IPC, no settings channel, no new dependency, no network call. The phase adds no app action, no control and no window.

**CTO library/format ruling (locked).** The ONE icon source is `lucide-react` (already a dependency: `package.json:38`, ISC, 24x24 grid, vector, tree-shakeable, offline). No second icon library, no icon font, no raster/PNG UI icons, no emoji, no runtime fetch. A metaphor Lucide genuinely lacks is drawn as a local SVG on the same 24x24 grid with the SAME normalized stroke inside the single icon module below - never as an ad-hoc inline `<svg>` in a component. App branding is deliberately NOT touched: the Phase 69/70 Jovrel brand kit, `src/renderer/components/BrandMark.tsx`, `BrandLoader.tsx` and the Phase 79 native `.ico` set stay as shipped (they are brand art, not tool icons).

**CTO RULINGS:**

1. **Scope and files.** Renderer only, app-wide. New: `src/renderer/icons/Icon.tsx` (the shared wrapper + `ICON_SIZES` scale + `ICON_STROKE`), `test/unit/renderer/phase94_iconSystem.test.tsx` and `test/unit/renderer/phase94_noAdHocIcons.test.ts`. Modified: `src/renderer/styles.css` (icon tokens only), and every renderer file that renders a UI icon, migrating it to the wrapper. Explicitly OUT: `src/main/`, `src/shared/`, `src/preload/`, IPC, `package.json`/dependencies, all functional/brand SVGs in ruling-current-state item 5, motion, button and dialog-shell styling. If frontend-dev finds a file it cannot migrate without a behaviour change, it stops and reports rather than widening scope.
2. **One central module.** `src/renderer/icons/Icon.tsx` exports `Icon` (a `LucideIcon` in, one rendered `<svg>` out) and the `ICON_SIZES` scale. Every UI icon in every named surface renders through `Icon`. Direct `<SomeLucideIcon size={...} />` renders in named surfaces are removed by this phase. The wrapper is the single place that sets `strokeWidth`, `strokeLinecap`, `strokeLinejoin`, `color`, `focusable` and `aria-hidden`.
3. **One normalized visual language.** `strokeWidth` comes from ONE token (`ICON_STROKE`, mirrored as `--tf-icon-stroke` in `styles.css`), `strokeLinecap="round"`, `strokeLinejoin="round"`, `color` is always `currentColor` (never a literal hex on a tool icon), and `focusable="false"`. The only permitted per-use stroke variation is an explicit `variant="bold"` on the wrapper (for marks inside a filled checkbox/selected swatch); every other per-call `strokeWidth` override is removed. No tool icon carries a literal `stroke`/`fill` colour.
4. **Sizes are tokens, not literals.** The wrapper takes a token name from `ICON_SIZES` (`xs` 14, `sm` 16, `md` 18, `lg` 20, `xl` 22, `hero` 32); `md`/`lg`/`xl` are the chrome floor and stay >= 18px per `def339_iconFloor.test.ts`. Named surfaces must not pass a raw pixel number. `xs`/`sm` are only for non-chrome marks (the on-page comment badge and equivalent inline indicators). No chrome icon renders below 18px after this phase; `AnnCommentIcon`'s 10px mark is raised to `xs` and the badge box grows to fit.
5. **Theme awareness and contrast.** Icon colour resolves through `currentColor` and the existing semantic tokens for each of light/dark/frosted; no icon participates in a colour rule that fails the existing contrast contract (`test/unit/renderer/designTokensContract.test.ts`). The before/after evidence must include both light and dark (and frosted) captures.
6. **Accessibility preserved.** The wrapper defaults `aria-hidden` to true (decorative), so a control's accessible name must continue to come from its label/`aria-label`/`title` exactly as today; the phase must not remove an existing accessible name and must not make an icon the sole carrier of meaning. The standing `CONTROL-INDEX` no-op sweep (every existing control still performs its shipped action) applies.
7. **No legacy/mixed icon remains.** The two inline `FormsOverlay` glyphs migrate to the wrapper (`Check` and `X`) so there are no hand-declared UI icons left outside the wrapper; any remaining raster, glyph-text or non-Lucide UI icon found during the sweep is migrated or reported. Functional/brand SVGs (item 5) stay and are allow-listed in the guard with a written reason.
8. **Guards (fail-loud, source-scan).** `phase94_noAdHocIcons.test.ts` scans `src/renderer/**/*.{ts,tsx}` for `<svg` UI icons and for lucide renders that bypass the wrapper in the named surfaces; it fails on any `<svg` outside the functional/brand allow-list and on any raw numeric `size={` on a named-surface icon. `phase94_iconSystem.test.tsx` pins the wrapper contract (defaults, token->px mapping, stroke token, `currentColor`, `aria-hidden` default) and asserts `ICON_SIZES` clears the 18px chrome floor. The Phase 43 uniqueness guard and `def339_iconFloor.test.ts` remain green (extend `def339` only if a new icon-size rule is added).
9. **CONTROL-INDEX.** This phase adds **no new app action, no control and no window**. It is a visual system change. The e2e/no-op sweep proves every existing control named in the Phase 43 `NAMED_FILES` list still performs its shipped action after the migration (same selectors, same hit-testing, same accessible names).
10. **Settings impact:** none. No new persisted `AppSettings` field, no change to any existing settings shape, no new settings channel and no credential. Renderer-only, offline; no network call is added.
