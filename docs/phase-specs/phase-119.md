## Phase 119 - Responsive and Accessibility overhaul: Adaptive Shell (phase issue TFL-1231; CEO commission from TFL-1224, 2026-10-08)

**Operator request (product terms, TFL-1231 / category handoff `Visual overhaul/Responsive and Accessibility/`).** Treat responsiveness and accessibility as cross-component behavior across the whole app, not an optional final skin. Implement the **Adaptive Shell** direction: the document rail, canvas and one relevant properties inspector stay usable while panel visibility adapts to available space; no feature is hidden merely because its button does not fit. Measure the real document viewport after native captions, title row, tab rail, siderail, attached panels, dock and footer, using layout tokens / container measurements rather than scattered viewport constants, and establish real logical breakpoints against native DPI (never derived from screenshot pixels). **Focus Layout** is a layout alternative only: it is not required, and if supported it must reuse the same state and handlers, never a second subsystem. Precedence: live-app refinements > design-decisions > illustrative visuals; Consistency Corrections and the unified semantic tokens stay in force. Offline-only: no network, remote collaboration, conversion service, mail or print execution from this surface. Truthful states only; existing command IDs, session / selection identity, undo / draft semantics, permissions and native Windows chrome are preserved; PDF pixels are never recolored and a document is never mutated merely by selecting a view or configuring options. This category OWNS the global responsive / accessibility rules; sibling categories apply them and this phase must not fork, duplicate or undo their work.

**CTO rulings:**

1. **Scope.** Renderer only: a new `src/renderer/design/layout.ts` and a new `src/renderer/hooks/useDocumentViewport.ts` (the ONE measurement / breakpoint source), the shell wiring in `src/renderer/App.tsx` (`.app-main` attributes, `appMainPanelStyle`, rail / inspector / dock / footer composition only), `src/renderer/components/DocumentRail.tsx`, `SideRail.tsx` / `StageRail.tsx`, `ViewStrip.tsx`, `ActionDock.tsx` / `MultiActionDock.tsx`, `Inspector.tsx`, `ContextPanel.tsx`, `components/panels/*`, `PaneThumbStrip.tsx`, `multiPaneLayout.ts`, `src/renderer/styles.css` (additive layout / a11y token and shell sections only), and renderer unit tests. qa owns `e2e/**`, `screenshots/**`, `test-fixtures/**`. **No `src/shared/` contract change, no new IPC, no new `AppSettings` field, no dependency, no network, no backend chunk**: every persisted layout preference already exists (`panelLeftWidthPx`, `panelRightWidthPx`, `inspectorCollapsed`, `pagesPanelCollapsed`, `navigatorLayout`, `navigatorSplitRatio`, `theme`, `animationsEnabled`, `homeMotionPaused`).
2. **Measure, never hardcode.** ONE `useDocumentViewport` primitive computes the actual document viewport width from real container measurement (ResizeObserver, mirroring the existing `ActionDock.tsx:425-461` / `:519-574` pattern) after native captions, title row, tab rail, siderail, attached panels, pane navigator, dock and footer allocations. Breakpoints are logical-pixel thresholds declared once in `layout.ts` and mirrored as CSS custom properties; no screenshot-pixel constant, no scattered `window.innerWidth` comparison, no per-call-site media query. Distinguish OS display scale (`window.devicePixelRatio`), app UI scale (no such control exists today - recorded, never invented) and PDF zoom (existing View Strip), and never conflate them.
3. **Document rail.** The colorful rail keeps a readable explicit minimum tab width plus a complete All-tabs switcher; optional utilities collapse before filenames and stay reachable through a labelled overflow menu; titles ellipsize with a full accessible name and focus / hover tooltip. No unreadable title slivers; tab identity stays stable and confined to the rail.
4. **Dock.** The dock centers inside the measured document viewport (never the raw window), promotes its most useful actions plus a More overflow when space is constrained, and keeps keyboard and pointer alternatives to horizontal scrolling. No action is reachable only by a clipped or scroll-hidden control.
5. **One properties surface.** At most one active attached properties inspector is open at a time. The pane navigator has an accessible collapse and a labelled reopen control; the app never collapses both navigator and inspector with no recovery path. Every automatic layout change preserves panel widths, collapsed states, drafts, selections and user preferences, and preferred geometry is restored when space returns.
6. **Controls and logical pixels.** Controls provide at least 32 px fine-pointer and about 44 px coarse-pointer targets with no invisible hit-area overlap; everything is logical pixels honoring Windows text / display scaling including 200% without overlapping labels or targets. Fonts are never shrunk to solve overflow. Long and localized labels reflow or ellipsize with full accessible names plus focus / hover tooltips.
7. **Semantics, focus and Escape.** Use framework-native semantic tabs, trees, menus, dialogs, toolbars, inputs and separators. Define one coherent focus order across chrome, navigation, canvas, dock and inspector; visible focus is independent of selected / hover. Escape closes only the topmost transient surface and restores its correct opener without discarding unrelated document edits. Dialogs trap focus, inert the background and expose title / description; attached panels do NOT trap focus. No nested interactive elements; shortcuts retain scope and never conflict with typing, IME or screen-reader keys; the shortcuts reference lists actual registered accelerators.
8. **Contrast, forced colors, motion.** Light / dark semantic contrast meets 4.5:1 for small text and 3:1 for meaningful non-text boundaries / states. High contrast uses the OS forced-colors path (`forced-colors`, `prefers-contrast`, system color keywords), not the prototype switch, with visible markers / checkboxes / labels, solid boundaries and native focus surviving custom layers. No status depends on a specific violet or a unique tab hue. Reduced motion removes nonessential transitions and decorative Home motion; nothing loops merely to look modern.
9. **Regression matrix.** Validate with the real app rather than markup mirrors: real commands and drafts at restored / maximized / minimum window sizes, 100/125/150/200% Windows display scaling, 200% text scaling, keyboard-only use, screen reader, high contrast, reduced motion, touch and mixed-DPI monitor changes. Test PDF viewport anchors separately from UI layout.
10. **Focus Layout is optional.** It is NOT required. If implemented it must reuse the same state and handlers as Adaptive Shell; no second layout subsystem, no parallel store. The phase must not present a dead Focus control.
11. **Seams reconciled, never duplicated.** This phase introduces the global layout / scale / breakpoint / target-size / focus / contrast primitives and applies them to the shell; sibling categories (Siderail, Panels, Dock, Top Bar and Tabs, Buttons, Typography, Canvas, Viewing Controls, Thumbnails and Outline, Dialogs Toolboxes and Menus, Consistency Corrections) keep ownership of their chrome and are applied, not forked or rewritten. Reuse existing command / menu / dialog / operation primitives; no parallel store, no per-call-site CSS override.
12. **Truthful states, pixels and identity.** Bind actual data; no placeholder command, prototype fixture state or scenario control ported into production. Preserve command IDs, session / selection identity, undo / draft semantics, permission checks, save / close / cancellation policy and native Windows chrome. Never recolor a PDF pixel or mutate a document merely from selecting a view or configuring options.
