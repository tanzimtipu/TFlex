## Phase 124 - Page panel: retire the "More" overflow into direct tool icons and unify both side-panel collapse controls to one directional arrow (phase issue TFL-1417; CEO commission from TFL-1416, 2026-10-09)

**Operator request (product terms, TFL-1417 from TFL-1416).** In the page view panel, remove the "More" overflow control and surface the tools it currently hides as direct, individually reachable icon buttons inside the panel - no secondary menu. On both side panels, replace the current collapse/expand icons with a single simple arrow that changes direction with the panel state, matching the attached reference screenshot (a single thin chevron whose direction follows the way the panel will move). Page-view behavior is otherwise unchanged and no previously reachable tool is lost. Offline renderer UI only; no network features.

**CTO rulings:**

1. **The target "More" is the PAGES ContextPanel header button - the only control that renders the literal text "More".** It is `[data-context-panel-more]` (`src/renderer/components/ContextPanel.tsx:1621-1638`), whose CommandMenu (`panelMoreGroups` / `panelMoreNode`, `ContextPanel.tsx:690-760`) holds three entries: the navigator layout toggle (`[data-context-panel-layout-split]`, always present), "Combine with another PDF" (`[data-context-panel-combine]`, only when `onMerge` is wired) and "Remove blank pages" (`[data-blank-scan-open]`, only when `onRemoveBlankPages` is wired). All three become their own direct icon buttons in the same header; the More button and its popover are removed with no dead code. The other "More" affordances in the shell - the per-thumbnail card footer menu (`[data-thumb-more]`) and the outline per-row menu (`[data-outline-more]`) in `SideRail.tsx`, and the narrow-width viewing `[data-view-strip-more]` in `ViewStrip.tsx` - are explicitly OUT OF SCOPE.
2. **The arrow is ONE directional chevron per panel; the existing hooks are frozen.** Both collapse controls keep their class, `data-*` hooks, `aria-expanded`, accessible labels, `onClick`, `disabled` and focus-return refs unchanged; only the glyph changes. The arrow points the way the panel will move: the LEFT panel shows a left chevron (`ChevronLeft`) when expanded (it will collapse left) and a right chevron (`ChevronRight`) when collapsed (it will expand right); the RIGHT Inspector shows a right chevron when expanded (it will collapse right) and a left chevron when collapsed (it will expand left). Reference: the attached chevron screenshot (asset `2c22a843-9068-4ae1-b545-e5c3d7b44ded`).
3. **Renderer only, minimal, no contract change.** Touch `src/renderer/components/ContextPanel.tsx`, `src/renderer/components/Inspector.tsx`, `src/renderer/styles.css` and the affected renderer unit specs. No `src/shared/` contract change, no IPC, no new `AppSettings` field, no main-process work, no new dependency, no backend chunk.
4. **No secondary menu and no lost tool.** Each surfaced tool is a real, individually clickable `IconButton` with a descriptive `aria-label`; a click performs exactly what the former menu row did (`onNavigatorLayoutChange`, `onMerge`, `onRemoveBlankPages`). Nothing is disabled, hidden or stubbed.
5. **Enforcement and evidence.** A new focused renderer spec pins the removed More and the three direct controls (each firing its handler) and both chevron flips while the frozen hooks still resolve; the existing navigator-chrome and inspector specs stay green; real-app before/after screenshots at the default window size prove the More is gone, the three icons are present, and each panel's arrow flips. No adversary chunk is scheduled: the change is presentation-only with no save / export / delete / settings-persistence surface, matching the Phase 122 precedent.
