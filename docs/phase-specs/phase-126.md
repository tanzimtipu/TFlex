## Phase 126 - Canvas warning/error notices: restore the collapse-to-"i" rule and retire the floating warning/error popups (phase issue TFL-1400; CEO commission from TFL-1398, 2026-10-09)

**Operator request (product terms, TFL-1400).** On the document canvas, warning/error notices must follow the app's established notice rule instead of the newer popup behaviour: the notice appears as a rounded, slightly translucent box INSIDE the canvas (never outside it), entered from the small "i" (info) icon pinned at the canvas top-right - immediately left of the Book View control with tight spacing - which morphs/expands into the message box; after 10 s the box collapses smoothly back into the "i"; a user expand resets the dwell; expand/collapse stays animated, and `prefers-reduced-motion` / `:root[data-animations="off"]` take the instant path. This is the previous rule exactly as specified in TFL-187 and implemented via `useNoticeCollapse` (`NOTICE_AUTO_COLLAPSE_MS = 10000`) across Phase 67/73/78. The operator directs: "retire the new one." Asked which current canvas popup is the newer mechanism, the operator answered "All floating warning/error popups over the canvas" - route every warning/error popup through the restored in-canvas "i"-collapse notice. Offline renderer UI only; no network features.
