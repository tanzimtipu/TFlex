## Phase 90 - Bates placement, edit/delete and the unified review-element inspector (FEA-033 follow-up correction, TFL-509 / user report TFL-508, 2026-10-03)

**Operator request (product terms, TFL-509 / TFL-508):** Phase 89 shipped Bates numbering as an apply-only stamp clamped to a 10%-margin 3x3 slot, with a text-only preview, no way to edit an applied run, and review panels that list annotations only. The operator requires: (1) placement anywhere on the page, including the edge, corner and gutter, not just inside the text margin; (2) a graphical on-page preview comparable to the Phase 18 watermark tool, replacing the text-only preview; (3) an applied Bates number that can be selected and edited afterwards (at minimum its position and its formatting/numbering parameters); (4) the context panel and the inspector panel to list **all** review elements grouped by category - annotations, Bates numbering, watermark, signatures - with select, edit and delete applied to the document; (5) fully offline; (6) fail-loud, honest reporting preserved.

**Relationship to Phase 89, Phase 18 (watermark), the Phase 12 stamp palette and the review panels.** Phase 90 is a **correction and extension** of Phase 89 - it does not rewrite the Phase 89 contract, it supersedes exactly two Phase 89 clauses: Ruling 7 ("position is the shared 3x3 slot ... no explicit x/y override") and the "this phase does **not** add list/delete ops for Bates markers" sentence in Ruling 5. Everything else in Phase 89 stays in force. It adds explicit `x`/`y` to `BatesSettings` (mirroring the Phase 45 watermark custom coords, `types.ts:1642-1643`, `WatermarkDialog.tsx:57-76`, `:359-371`), makes each Bates application addressable through its content-stream marker (mirroring the Phase 18 watermark marker/scan/delete path, `engine.ts:271-293`, `:4496-4630`), and adds one shared reviewer element-list component re-parented by both the ContextPanel and the Inspector (mirroring how `AnnotationsPanel` is re-parented today, `ContextPanel.tsx:583-588`, `Inspector.tsx:584-597`). No window, no new document model, no second settings channel and no network.

2. **Arbitrary placement is explicit page coordinates, not a bigger slot.** Extend `BatesSettings` with `x?: number` and `y?: number` (points, top-left origin, matching the Phase 45 watermark custom-coord convention). When **both** are finite the engine places the label's top-left at `(x, y)` and clamps only to the page bounds (`x in [0, pw - w]`, `y in [0, ph - h]`) - no 10% margin, so edge/corner/gutter are reachable (`x=0,y=0` = top-left corner). When either is missing the existing Phase 89 3x3 slot maths (`engine.ts:4438-4449`) is used unchanged. `x`/`y` are validated finite and within `0..MAX_BATES_COORD = 14400`; an out-of-bounds or non-finite coordinate is a typed `engine-error` and the whole op is refused (fail-loud, Ruling 7). The stamp must render at the chosen position on save, reload and text extraction.
3. **The Bates application becomes addressable.** Each Bates content stream's first line stays `%TFLEX-BATES ` + base64url JSON but the JSON now carries the full run record: `{ id, page, label, settings }` where `settings` is the `BatesSettings` (with `x`/`y` when used) that produced the run. Add `readBatesMarker(contents)` (mirror `readWatermarkMarker`, `engine.ts:271-293`) and `_scanBatesMarkers(doc): BatesInfo[]` that group markers by `id`, preserving page order and collecting the parallel `labels`. The marker remains the single source of truth for "what was applied". A marker written by Phase 89 without `settings` (pre-Phase-90 file) still lists (`BatesInfo` with the parsed available fields) and **can be deleted**; editing it is refused with a readable `engine-error` ("this Bates run was applied by an older version; delete and reapply") - never a silent partial edit.
4. **Three new Bates engine ops, all all-or-nothing and single-undo.** `engine.getBates(docId): Result<BatesInfo[], EngineError>` on channel `engine:getBates`; `engine.updateBates(docId, id, settings: BatesSettings): Result<BatesResult, EngineError>` on channel `engine:updateBates`; `engine.deleteBates(docId, id): Result<EngineState, EngineError>` on channel `engine:deleteBates`. `updateBates` removes every content stream of that run and re-bakes the run with the new `settings` in exactly **ONE** `snapshotDocWithPdf` (one undo entry), validating the new payload exactly as `_addBatesImpl` does; `deleteBates` removes every stream of the run in exactly ONE snapshot. Both enqueue through `_enqueue` and set `doc.modified = true` on change. An unknown `id` is a typed `engine-error` and mutates nothing.
5. **`BatesInfo` is the shape the panels consume.** `interface BatesInfo { id: string; prefix: string; suffix: string; startNumber: number; padding: number; position: WatermarkPosition; x?: number; y?: number; font?: EditFont; size: number; color?: EditColor; pages: number[]; labels: string[] }`.
6. **One unified review-element list, re-parented by both panels.** Add `src/renderer/components/ReviewElementsPanel.tsx`: a category-grouped list with the categories **Annotations**, **Bates numbering**, **Watermarks**, **Signatures**. Annotations re-parent the existing `AnnotationsPanel` unchanged (`AnnotationsPanel.tsx:189-234`). Each non-annotation row has a select (jump to the page), an edit and a delete control with stable hooks (Ruling 10). `ContextPanel` REVIEW (`ContextPanel.tsx:572-637`) and `Inspector` REVIEW (`Inspector.tsx:112-133`, `:584-597`) both render it, grouped by the same categories. Selecting a row jumps the workspace to that element's page (mirror `onJumpToAnnotation`, `DocumentView.tsx:3529-3555`); editing and deleting call the owning engine op and refresh the document proxy plus the list.
7. **Watermark and signature rows also get edit/delete.** Watermarks already list (`getWatermarks`) and delete (`deleteWatermark`); add `engine.updateWatermark(docId, id, settings: WatermarkSettings): Result<EngineState, EngineError>` on channel `engine:updateWatermark`, implemented as remove-the-run + re-bake in ONE snapshot (mirror `updateBates`), and let `WatermarkDialog` open in an update mode prefilled from the row's `WatermarkInfo` so the panel's edit action reuses the shipped form. Signature rows select/jump and delete through the existing `engineDeleteSignature`; their "edit" is the existing on-canvas move/resize placement reached by selecting the row. Every listed item therefore supports select, edit and delete.
8. **Offline only.** No network, cloud, account or subscription call is added anywhere; no credential is introduced.
9. **Fail-loud, never a silent skip.** A reject in any new op (bad/out-of-bounds coordinate, unknown id, unencodable label, out-of-range page) is a readable typed error; the dialog shows it in `[data-bates-report]` and the panel shows it in a readable row-level error slot; nothing is partially mutated.
10. **Stable e2e hooks (CONTROL-INDEX).** See the CONTROL-INDEX section; no separate open hook is added for the Bates dialog beyond the existing `[data-dock-verb="bates"]`.
11. **No regression** to the Phase 89 apply path, the Phase 18 watermark apply/get/delete, the Phase 12 stamp palette, annotations, page rendering/zoom, save/export, undo/redo or settings persistence. The new `settings` field on the Bates marker is additive; the Phase 89 e2e assertions on labels-on-pages, one-undo, save/reload and refusal must still pass.

**Success criteria**

1. Placement is not clamped to the page margin: a user can place the Bates stamp anywhere on the page, including the edge, corner and gutter, and after apply + save + reload the stamp renders at that position (text extraction finds the label and the drawn label's page location matches the `x`/`y` payload).

3. An applied Bates run can be selected from the unified review list and edited (at minimum its position and its formatting/numbering parameters), and the document updates accordingly as one undo entry.
4. The context panel and the inspector panel both list all review elements grouped by category (annotations, Bates numbering, watermarks, signatures), and each listed item can be selected, edited and deleted from those panels with the change applied to the document.
5. Offline only: no network, cloud, account or subscription access is introduced by the phase.
6. Fail-loud, honest reporting is preserved: any element that cannot be placed, updated or deleted is reported to the user with a readable message and mutates nothing; no selected page or element is silently skipped.
