## Phase 100 — Centralized element foundation: per-family modules, usage contract, drift guards and retrofit (phase issue TFL-729; source request TFL-556, 2026-10-04)

**Operator request (product terms, TFL-556 / phase issue TFL-729).** Every shared
visual/behavioural element family — colour/theme, typography, spacing, radii,
elevation/shadow, motion/animation and iconography — must have ONE authoritative,
documented foundation with a stable public API; feature code must consume that
foundation instead of inventing local values, so every future feature inherits the
same language; automated guards must fail on drift (raw literals, one-off
animations); and switching themes must change every element consistently. Offline
only; no network feature.

**CTO RULINGS:**

1. **Scope.** Renderer only. No main-process change, no new IPC channel, no
   settings field, no new window, no network. frontend-dev owns
   `src/renderer/design/**` (new), `src/renderer/styles.css`, the re-export
   surface of `src/renderer/hooks/motionTokens.ts`,
   `test/unit/renderer/foundation*.test.ts` and `docs/DESIGN-SYSTEM.md`. qa owns
   `e2e/**`, `screenshots/**`, `test-fixtures/**`. No engine/convert/settings code.
2. **Foundation module per family.** Create `src/renderer/design/` with one module
   per family — `color.ts`, `typography.ts`, `spacing.ts`, `radii.ts`,
   `elevation.ts`, `motion.ts`, `icons.ts` — plus `index.ts` as the stable public
   API. `motion.ts` RE-EXPORTS `MOTION_*`/`msToSeconds` from
   `src/renderer/hooks/motionTokens.ts` and `icons.ts` RE-EXPORTS
   `ICON_SIZES`/`ICON_STROKE`/`ICON_STROKE_BOLD` (+ types) from
   `src/renderer/icons/Icon.tsx` — never a second copy. The remaining modules are
   TYPED MIRRORS of the CSS tokens with the exact values, pinned by
   `test/unit/renderer/foundationMirrors.test.ts` (mirror the CSS-parse pattern of
   `animationsTokens.test.ts`). Each module's header names its CSS source of truth.
3. **One canonical name per value; aliases preserved.** `--sp-*` stays canonical
   for spacing; `--space-*` becomes verified aliases (`--space-micro: var(--sp-1)`
   etc.). `--radius-1..3` plus `--radius-window/panel/group/control/pill` stay
   canonical; `--tf-radius-*` becomes aliases. Canonical motion names stay
   `--tf-motion-*`/`--tf-ease-*`; `--motion-*`/`--ease-*` aliases stay. Canonical
   colour names stay `--accent*`; `--tf-accent*` aliases stay. NO mass rename of
   existing usages — aliases keep every existing rule working; only alias
   definitions are added and the canonical set is documented.
4. **Drift guard.** `test/unit/renderer/foundationGuards.test.ts` (node, mirroring
   the explicit-list pattern of `phase94_noAdHocIcons.test.ts`): (a) a
   `MIGRATED_SURFACES` list of renderer source files that must contain no raw
   literal for an enforced family — raw hex colour in a style context, raw numeric
   `fontSize`, raw numeric `borderRadius`, raw `boxShadow`, raw numeric
   `padding`/`margin`/`gap` — with a small written `ALLOWLIST` for data/functional
   literals (annotation colours, canvas raster, brand art); (b) a CSS scan over
   `src/renderer/styles.css` rule bodies OUTSIDE the token-definition blocks
   (`:root`, `[data-theme=...]`, `@property`) that must not declare a raw
   `box-shadow`, `border-radius` or `font-size` where a token exists. The list
   starts as the files/families migrated in each chunk and must GROW to cover
   `src/renderer/**/*.tsx` and the whole stylesheet by phase end.
5. **Motion one-off guard.** Extend the motion contract so any `transition:` or
   `animation:` in a migrated rule body references a
   `--tf-motion-*`/`--motion-*`/`--tf-ease-*` token (or `none`): no raw ms/s
   duration and no raw `cubic-bezier(` outside the token-definition blocks.
6. **Theming = foundation.** `foundationMirrors.test.ts` also asserts three-scope
   parity: every semantic colour role (`--sem-*`, `--info/success/warning/error`
   and their `-soft`, and the surface/foreground roles documented in
   `docs/DESIGN-SYSTEM.md`) is declared in all three scopes (`:root`,
   `:root[data-theme="dark"]`, `:root[data-theme="frosted"]`), so a theme flip
   cannot leave an element unmapped.
7. **Usage contract.** Append a "How a feature consumes the foundation" section to
   `docs/DESIGN-SYSTEM.md`: the module imports, the rule that new/changed code uses
   tokens (never literals), the canonical-vs-alias table, the reduced-motion rule
   and the exact guard command. The document and the token layer must agree,
   pinned by the tests.
8. **Tests prove it.** Unit oracles as above plus `npm run verify`; qa runs the
   theming e2e in all three themes with screenshots; the adversary diff-passes;
   phase-close QA and a single local commit close the phase.
9. **Settings impact:** none. No new persisted `AppSettings` field, no settings
   channel, no credential. Offline only.
10. **Numbering.** This is Phase 100 (the last appended phase is 99). Its artifacts
    are named `phase100_*` / `foundation*` so they stay unambiguous.
