## Phase 101 — Always-on background bug capture to Neon (`public.bug_reports`) (phase issue TFL-739; source request TFL-543, 2026-10-04)

**Operator request (product terms, TFL-543 / phase issue TFL-739).** Every unhandled
failure in the Jovrel desktop app - an uncaught main-process exception, an unhandled
promise rejection, a rejected IPC handler, a React render crash, a `window.onerror` or
an `unhandledrejection` in the renderer - must be captured automatically and silently
with enough detail to reconstruct and fix it, then persisted to the company Neon
database so an automated fix routine can triage it. There is NO user-facing bug dialog
and no manual submission UI. Capture is always on and must never block startup or any
UI action, and must survive the app being offline.

**CTO RULINGS:**

1. **Scope.** One new main-process service (`src/main/services/bug-report/**`), one new
   shared contract (`src/shared/bugReport.ts`) plus IPC additions in `src/shared/ipc.ts`,
   the preload bridge in `src/preload/preload.ts`, wiring in `src/main/index.ts`, and
   renderer capture in `src/renderer/bug-report/**` wired from `src/renderer/main.tsx`.
   No new window, no user-facing dialog, no settings field, no third-party SaaS. qa owns
   `e2e/**`, `screenshots/**`, `test-fixtures/**`.
2. **Ingest = the existing Neon Data API.** A dedicated `BugReportTransport` mirrors
   `src/main/services/accounts/transport.ts` and INSERTs into `public.bug_reports` via
   `NeonPostgrestClient` using the Data API URL from `getAccountsConfig`. Bug reports
   are sent WITHOUT a user JWT (a crash before sign-in must still be captured); the Data
   API maps an unauthenticated request to the `anonymous` role. `user_id` is sent as a
   plain column value only when a session is held, for triage - it is not an auth
   boundary. No `fetch(` and no URL literal in `src/` (the conventions gate).
3. **Required infra change (flag to CEO first).** `GRANT INSERT ON public.bug_reports
   TO anonymous;` with RLS left OFF and NO SELECT/UPDATE/DELETE granted to any client
   role - the client path is append-only. This is the only schema/permission change; it
   is raised to the CEO as a child issue and must be authorized and applied before the
   live e2e. The code is built and unit-tested against a fake transport meanwhile, so
   this is a soft dependency for the code and a hard dependency for live persistence.
4. **No new credential.** The Data API URL is already shipped in the `tflex` block and
   read at runtime; the shipped client embeds no privileged connection string.
5. **Capture points.** Main: `process.on('uncaughtException')` and
   `process.on('unhandledRejection')` registered as early as the main entry allows, and
   a wrapper for `ipcMain.handle` that captures a rejected handler (registered once, so
   existing handlers keep working), plus a `bugReport:capture` IPC channel the renderer
   forwards to. Renderer: one root `BugReportErrorBoundary` around `<App />` in
   `src/renderer/main.tsx`, `window.addEventListener('error')` and
   `window.addEventListener('unhandledrejection')`, all forwarding through
   `window.tflex.bugReport.capture(...)`.
6. **Record shape** follows `src/shared/bugReport.ts` and matches the table columns.
   `session_id` is a per-process UUID; `breadcrumbs` is a bounded ring (last 50);
   `context` is free-form and redacted. `environment` is `production` unless overridden
   by a dev/test env var; `build` is the app version plus update channel when available.
7. **Bounded queue + opportunistic flush.** The queue is persisted at
   `{userData}/bug-reports-queue.json`, capped at 200 entries (drop-oldest), flushed on
   a debounce and at startup in a single-flight, fire-and-forget manner that NEVER
   throws, with exponential backoff on failure. A failed flush must not crash-loop and
   must not block startup or any UI action. Capture itself is in-memory and synchronous;
   the network write is always off the UI path.
8. **Fingerprint + hot-loop dedup.** A stable fingerprint is a hash of `error_name` +
   normalized message + the top stack frame (`file:line`, path-normalized) + `component`.
   Repeated occurrences of the same fingerprint within a short window are collapsed into
   a bounded occurrence `count` in `context` rather than a new row, so a hot error loop
   cannot amplify writes without bound.
9. **Redaction is mandatory.** A pure `redact()` strips Bearer/JWT tokens, key/value
   pairs matching `token|password|secret|authorization|api[-_]?key`, and maps
   home-directory user names to `<user>`. Document bytes and user file contents are never
   captured. A unit test table of secrets must prove each class is removed.
10. **Tests prove it.** Backend unit tests for fingerprint, redaction, queue bounds,
    flush backoff and the transport call shape (fake transport); renderer unit tests for
    the boundary and the global handlers; a focused e2e (qa) that forces one main error
    and one renderer error and proves each yields a row in `public.bug_reports`; `npm run
    verify` clean; the adversary diff-passes the capture path; phase-close QA and ONE
    local commit close the phase.
11. **Numbering.** This is Phase 101 (the last appended phase is 100). Artifacts are
    named `phase101_*` / `bugReport*` / `bug-report*` so they stay unambiguous.

**Phase 101 correction - CTO ruling (2026-10-04, after DEF-548).** Ruling 2's ingest
