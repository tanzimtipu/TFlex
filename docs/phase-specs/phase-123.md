## Phase 123 - Chrome-style document tabs: size, silhouette and behavior (phase issue TFL-1403; CEO commission from TFL-1344, 2026-10-09)

**Operator request (product terms, TFL-1403 from TFL-1344).** Make the TFlex document tab strip read and behave like Chrome browser tabs, using the screenshot attached to TFL-1344 as the visual reference: Chrome tab **size and behavior**, the distinct look of the **active** tab (the raised light tab among the right-hand tabs), and Chrome's subtle **hover** treatment on inactive tabs. Offline renderer UI change; no network features.

**CTO rulings:**

1. **Chrome is a NEW first-class `TabStyle` value and becomes the DEFAULT.** `TabStyle` (`src/shared/types.ts:104-108`) grows from `'standard' | 'colorful'` to `'standard' | 'colorful' | 'chrome'`; `DEFAULT_SETTINGS.tabStyle` (`src/main/services/settings.ts:324`) and the renderer `DEFAULT_TAB_STYLE` (`src/renderer/state/preferences.ts:37`) both become `'chrome'`. Rationale: the operator's reference is Chrome and the strip must read as Chrome out of the box, but the completed Phase-45/51/58/62/68/72/105 identity work and the `'standard'`/`'colorful'` looks are NOT re-opened - they stay selectable and unchanged through the existing Tab style setting. If the operator instead wants the colorful default itself repainted Chrome, that is a follow-up amendment, not this phase. This ruling is flagged for the operator in the phase report.

2. **The Chrome look is the muted-inactive / raised-active relationship from the reference.** Inside `[data-tab-style="chrome"]`: an inactive tab is a muted surface (the strip's toolbar surface, no per-session hue) with rounded top corners and a flush bottom edge; the active tab is the raised, lighter/contrasting surface connected to the content below - it fills the strip's foot, squares its bottom corners and leaves no separating border/line between it and the document surface. Exactly one tab reads active at all times and it always tracks the actually-open document (the existing `active` / `aria-selected` contract is unchanged).

3. **Hover is strictly visual and affects inactive tabs only.** Hovering an INACTIVE tab subtly lightens its body (a background lighten - never a transform or filter on the active tab) and reveals/highlights its close control, with **no layout shift** (no width / height / margin / transform change, no reorder, no active change). The active tab is never hover-lightened.

4. **Close and "+" are real, Chrome-behaved controls.** Each tab's close control is hidden at rest on an inactive tab and appears on the active tab and on hover / focus-visible, with its own hover state; the strip ends with a Chrome-style "+" new-tab button. Both are the existing working controls - `.tab-close` (`AnimatedTab.tsx:230-242`) and `[data-new-tab]` / `.tab-new` (`DocumentRail.tsx:981-1001`) - restyled, never replaced or stubbed; the Multi-Mode disabled reason on the "+" is preserved.

5. **Design-system and behavioral contracts are preserved.** Use the existing design tokens (no invented values), keep the `.tab:focus-visible` ring, the reduced-motion / Animations-OFF catch-alls (`docs/ANIMATION-RULES.md`, `styles.css`, `src/renderer/hooks/motionTokens.ts`), and the tab ARIA semantics (`role="tablist"` / `role="tab"` / `aria-selected`); open / close / switch / reorder / tear-out and the document-identity the strip reflects must not regress. Behavior holds across supported window sizes; the header / strip height is not changed.

6. **Renderer only, apart from the contract / default value.** A `src/shared/` contract change (`TabStyle`), the `settings.ts` allowed-value set and default, and a main-process test update; everything else is renderer (`styles.css`, `DocumentRail.tsx`, `preferences.ts`, `defaults.ts`, `PreferencesDialog.tsx`) plus one renderer unit spec. No IPC shape change, no new `AppSettings` field, no backend engine / packaging work, no network.
