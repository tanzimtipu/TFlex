## Phase 87 - Remove blank pages (FEA-039, commissioned via TFL-315 / TFL-426, 2026-10-02)

**Operator request (product terms, TFL-426):** let a user **scan a document for pages that carry no renderable content**, or only scanner noise below a **user-adjustable ink-coverage threshold**, see those pages listed, and **delete the confirmed ones in a single pass**. This is the cheapest scan-cleanup win and complements OCR (Phase 11) for paper workflows. Offline only; no network feature.

**Relationship to Phase 2 (page organization), Phase 11 (OCR) and the app's raster pipeline.** Deleting a page already exists and is well tested: `engine.applyOp(docId, {kind:'delete', page})` on channel `engine:applyOp` (`ipc.ts:150`) routes to `applyOpToDoc` (`engine.ts:5072`), whose `delete` case (`engine.ts:5091`) drops the page from `doc.order`, removes its annotations, and shifts placed signatures and text boxes so visible numbering stays consistent. This phase **does not touch that path**; it adds the *detection* that decides which pages to delete and one **batch delete op** that reuses the same per-page delete so a multi-page removal is one undo entry. Page rendering for the scan reuses the renderer's existing pdf.js DOM-canvas rasteriser (`rasterizePagesForOcr`, `ocrRasterize.ts:247`; `OcrPageImage`, `types.ts:1253`), which exists because pdf-lib cannot rasterise and a main-process pdf.js render previously crashed the native canvas backend (`ocr.ts:13-17`). The phase adds one pure shared module, the shared contract, one engine op / one IPC channel, the preload/main wiring, one renderer raster helper and the renderer scan dialog. It adds no window, no new document model and no network.

**Capability boundary (honest, non-negotiable).** "Blank" is defined **only** by measured ink coverage on a rasterised page: a truly empty page renders to white (coverage ~0), and a scan-noisy page renders a low but non-zero coverage. The scan therefore **must rasterise every page it inspects**, and it **measures pixels, not semantics** — a page that is visually blank but carries invisible/off-page content may still be reported as a candidate, and a page that the rasteriser cannot decode or render is **reported as unclassified, never silently dropped**. The phase refuses to guess: a page whose render throws is reported, not assumed blank; the operation is offline and deterministic.

**CTO RULINGS:**

1. **Scope is one new pure shared module, the shared contract (types + ipc), the main-process engine op + preload/main wiring, one new renderer raster helper and the renderer scan dialog.** Files: `src/shared/blankPages.ts` (new, pure), `src/shared/types.ts` and `src/shared/ipc.ts` (contract), `src/main/services/engine.ts` (the op), `src/main/index.ts` (handler), `src/preload/preload.ts` (bridge), the new `src/renderer/pdf/blankScan.ts`, the new `src/renderer/components/BlankPagesDialog.tsx`, and the renderer wiring `src/renderer/App.tsx`, `src/renderer/engine/{engineClient,types,stubEngine}.ts`. No new window, no new document model, no network.
2. **Detection is renderer-side raster ink-coverage, over the existing pdf.js path.** The renderer rasterises each page to a canvas at a low scan DPI (default 96, matching the OCR precedent's 72 DPI user-space scale = dpi/72, `ocrRasterize.ts:321`) and reads the pixels with `getContext('2d', {alpha:false})` + `getImageData()`, exactly mirroring `rasterizeOnePage` (`ocrRasterize.ts:297`) including its DEF-050 rule: **never call `doc.destroy()`** — the session document's lifetime is owned by the host; per-page cleanup uses `pdfPage.cleanup()`. No PNG encoding is needed (the pixels are consumed in-process by the pure module). The scan runs page-by-page with an `AbortSignal` and an `onProgress` callback so the renderer never blocks.
3. **One shared, pure source of truth for the measurement.** New `src/shared/blankPages.ts`, pure (no `fs`, no Electron, no DOM, no canvas), exporting: `computeInkCoverage(pixels: Uint8ClampedArray | Uint8Array, width: number, height: number, opts?: { stride?: number; inkCut?: number })` returning `{ coverage: number; sampledPixels: number }` where `coverage` is the fraction of sampled pixels whose luminance is below `inkCut` (default `INK_LUMA_CUT = 200` on a 0..255 scale — i.e. clearly darker than paper); and `classifyPages(measurements: readonly BlankPageMeasurement[], threshold: number)` returning `{ candidates: BlankPageCandidate[]; unclassified: BlankPageUnclassified[] }` where a page is a candidate iff `measurement.coverage <= threshold`. Both functions are unit-tested directly, with no raster.
4. **One new engine op and one new IPC channel.** `engine.removeBlankPages(docId, payload)` on channel `engine:removeBlankPages`. `RemoveBlankPagesPayload { pages: number[] }` where each entry is a 1-based VISIBLE page. It returns `Result<RemoveBlankPagesResult, EngineError>` where `RemoveBlankPagesResult { state: EngineState; removed: number[]; skipped: BlankPageSkip[] }` and `BlankPageSkip { page: number; reason: string }`. The op validates the whole set first and is **all-or-nothing**: `pages` empty or every page targeted (which would delete the last page) is a typed `empty-range`; any non-integer / out-of-range / duplicate entry is a typed `out-of-range`; on refusal the document is left byte-for-byte unchanged. On success it takes exactly ONE `snapshotDoc`-based undo snapshot, deletes the targeted visible pages in DESCENDING order by calling `applyOpToDoc(doc, {kind:'delete', page})` once per page (so the surviving visible indices are unaffected by the removal of higher pages), pushes ONE undo entry, marks `doc.modified = true`, and returns the removed 1-based page numbers. `skipped` is reserved for a page the last-page guard refuses mid-batch and is normally empty; it is never used to hide a silent no-op.
5. **Fail-loud, never a silent no-op.** Renderer-side: a page whose rasterisation or pixel read throws is added to the scan report's `unclassified` list with a readable reason naming the page and the cause, is **not** offered as a candidate, and is shown in `[data-blank-scan-report]` (never blank after a run). If the whole scan produces no measurable page, the report says so and no deletion is offered. Engine-side: an invalid batch is refused with the typed error and applies nothing; the dialog shows the error text.
6. **The threshold is a persisted app setting, validated at the leading edge.** Add `AppSettings.blankPageInkThreshold?: number` — the ink-coverage fraction (0..1) at or below which a page counts as blank; default `DEFAULT_BLANK_INK_THRESHOLD = 0.005` (0.5%). It is validated preserve-if-valid in `src/main/services/settings.ts` `normalizeSettings` (the main-process normaliser that runs BEFORE any renderer reads the value — the leading edge), accepting only a finite number in `[0, 1]` and falling back to the default otherwise; it rides the existing AppSettings IPC channel so it survives restart. The renderer's scan dialog reads it for its initial value and writes it back on change. No new settings channel and no new credential. This is **independent of the Phase-86 `replaceText` contract** (`types.ts` / `ipc.ts` / `engine.ts`): the two phases are interleaved in the same release train, so Phase 87's contract edits must land **after** the Phase-86 build chunks have settled on the shared files (see the sequencing note below), and neither phase's field or channel depends on the other.
7. **No regression** to page delete / reorder / rotate, the page panel, save/export, Phase 11 OCR, redaction, or settings persistence; the new op reuses `applyOpToDoc`'s `delete` case so annotation/text-box/signature bookkeeping is inherited unchanged. The feature is fully offline (no network call, nothing leaves the machine).

**Features**

**Success criteria**
