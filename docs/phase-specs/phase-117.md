## Phase 117 - Selection and Manipulation overhaul: Inspector First (phase issue TFL-1229; CEO commission from TFL-1222, 2026-10-08)

**Operator request (product terms, TFL-1229 / category handoff `Visual overhaul/Selection and Manipulation/`).** Give Selection and Manipulation one consistent, truthful selection-and-manipulation surface so every selectable object type - native text objects / text runs, images, annotations, crop regions and supported form fields - is selected through ONE shared selection controller with ONE set of visual handles and the ONE existing property inspector, while each type keeps its OWN real engine operation. **Inspector First** is the direction: detailed properties live in the existing inspector and only the essential Apply / Cancel controls sit near the object. **Context Bar** is the layout alternative and, if supported, must reuse the same selection state and handlers rather than becoming a second subsystem. Truthfulness gates acceptance: one selection controller across object types shares visual geometry and event plumbing but never merges engine operations (a form widget is never turned into an ordinary text object; page transfer is never conflated with object drag); selection draws a 1 px violet boundary and 6-8 px visual handles in screen coordinates with larger invisible hit targets (`finePointerTarget: 32` / `coarsePointerTarget: 44`), and focus / hover / selected geometry / in-progress draft are separate states (no full-width glow, no opaque fill that conceals text); a common multi-object bounding region appears only where the engine actually supports transforming the objects together, and multi-select properties expose `Mixed` and deliberately scoped changes; the red Delete is never the default highest-salience control beside Apply and lives in a separated More action under the established policy; context controls are anchored to the visible selection's screen rectangle, transformed using crop / rotation / zoom / viewport scroll / spread layout, prefer below the selection, flip above near the footer and clamp horizontally inside the document viewport, never covering the selected text, rail, inspector, dock or viewing controls (an object too small / occluded moves its editor into the inspector instead of stacking overlapping toolbars), and there is only ONE comment entry surface; draft edits update an intentional preview transaction where the engine supports it - Apply commits exactly ONE supported undo unit, Cancel restores the original object and clears the draft - and where the engine already uses immediate edits / engine undo the existing model is preserved and the controls are labelled accordingly (never faked by changing DOM text), document / tool switching is handled deliberately (retain, confirm discard or commit by existing policy) and selection alone never marks the PDF dirty; resize / rotate / drag use device-independent transforms with capture / cancellation handling, preserve aspect ratio per the real modifier / control policy, honour page boundaries where required, expose numeric / keyboard alternatives and escape cleanly when pointer capture is lost, with snapping only where supported (a guide is not proof of the landing) and no rounding of PDF geometry to screen pixels; text editing preserves PDF font embedding / substitution rules, baseline, original content semantics and unsupported-content explanations, UI typography never becomes a document font, and editable text is never advertised merely because the renderer exposes a text layer; property changes respect permissions, signed-document state, annotation vs content differences and existing warnings; and neither selecting an object nor configuring a view ever recolors a PDF pixel or alters document content. Precedence: live-app refinements > design-decisions > illustrative visuals; Consistency Corrections and the unified semantic tokens stay in force. Out of scope: any network / cloud collaboration, any recolor of PDF pixels, and re-implementing any shipped overhaul category.

**CTO rulings:**

1. **Scope.** Renderer: the shared selection surface `src/renderer/components/selectableContent.tsx`, `src/renderer/components/{ContextToolbox,controlPlacement,Inspector,ContextPanel,MultiActionDock,ActionDock,CanvasPills,PageView}.tsx`, `src/renderer/annotations/{AnnotationOverlay,StampAnnotations,AnnotationToolbar,model}.tsx`, `src/renderer/edit/{EditOverlay,TextPropertiesPanel,model,geometry}.tsx`, `src/renderer/forms/{FormsOverlay,model}.tsx`, `src/renderer/App.tsx` (selection / edit / crop / page-transfer wiring only), `src/renderer/state/{multiMode,pageSelection,pageDrag,pageDragApply,toolsRegistry}.ts`, `src/renderer/styles.css` selection section, renderer unit tests, and the inventory in the issue `plan`. **No contract change is required in `src/shared/`**: every engine operation the controller drives already exists (`editTextRun` / `addTextBox` / `updateTextBox` / `editImage` for content, the annotation add / edit / delete path, the `cropPages` page-box path, the `page-organize` transfer path, `EngineState.textBoxes`, `EngineState.formFields`, `EngineState.annotations`). **No new IPC channel, no new `AppSettings` field, no dependency, no network, no new backend chunk.** qa owns `e2e/**`, `screenshots/**`, `test-fixtures/**`.
2. **One controller, no forks.** `selectableContent.tsx` is the ONE shared selection surface: `useSelectableDrag` (`:82`), `ContentGrip` (`:114`) and the shared action bar (`ContentActionBar`, `:194`) migrate every kind - annotation, stamp, text box, image, text run, crop region - onto the same geometry, hit-testing, drag / resize maths and action chrome; per-kind ENGINE operations stay separate (annotation edit / delete, `editImage` move / resize / replace / crop, `editTextRun`, `addTextBox` / `updateTextBox`, form fill, page transfer). Do not introduce a parallel store, a second selection reducer, a second coordinate system, or per-call-site CSS overrides; reuse `ContextToolbox` + `controlPlacement` (`clampControlPosition` `:55`, `placeControlNearAnchor` `:74`) for anchoring, `Button` / `IconButton` / `Icon` / `DialogShell`, the Panels Context Pair chrome (`PanelShell` / `PanelSection`) and the TfMotion wrappers.
3. **Inspector First, reusing the shipped inspector.** Detailed properties render in the existing `Inspector` (`:909`) - the re-parented `TextPropertiesPanel` for a selected text object / annotation and the `cropbox` / `page` / document sections already exist (`resolveInspectorState` `:152`, `inspectorSectionsForState` `:185`, `inspectorSelectionFor` `:267`, `renderAnnotationInspector` `:1253`) - and ONLY the essential Apply / Cancel (plus a separated More) controls sit beside the object. The selection must expose the object's REAL type and never present a form field, a page transfer or an annotation as an ordinary text object.
4. **Handle geometry and hit targets.** 1 px violet boundary + 6-8 px visual handles in screen coordinates; invisible hit targets `finePointerTarget: 32` / `coarsePointerTarget: 44` (the token values in `Design System/unified-ui.tokens.json` and `Specifications/component.tokens.json` are AUTHORITATIVE and supersede the earlier "approximately 24 px" wording in `design-decisions.md`; the report must note this discrepancy resolution). Geometry uses the 4 px spacing grid, 9 px control radius, 14 px floating-surface radius, 16-24 px content spacing and 140 ms emphasis transitions; attached panels use hairline boundaries, not floating shadows.
5. **Separate states.** Current focus, hover, selected geometry and in-progress draft are DISTINCT states with distinct styling; selection never paints a full-width glow or an opaque fill over text. Keyboard focus is visibly separate from selection (`:focus-visible`), and hover never implies selection.
6. **Delete is separated.** The red Delete button leaves the primary row: `ContentActionBar`'s `btn-danger` delete immediately after Confirm / Cancel (`selectableContent.tsx:276-288`) is replaced by an Apply / Cancel row plus a separated More action carrying Delete (and any other destructive verb) under the established confirmation / undo policy. No red Delete as the default highest-salience control beside Apply.
7. **Anchoring and collision.** Context controls reuse `ContextToolbox` / `controlPlacement`: anchored to the selection's screen rectangle and transformed by the existing zoom / scroll / crop / rotation / spread transforms (`Canvas` Phase 107, `Viewing Controls` Phase 109); prefer below, flip above near the viewing footer, clamp horizontally inside the document viewport; never cover the selected text, the rail, the inspector, the dock or the viewing footer; a too-small / occluded object renders its editor in the inspector instead of an overlapping toolbar; there is exactly ONE comment entry surface (the Thread Stream draft, Phase 116).
8. **Draft / Apply / Cancel / undo honesty.** Where the engine supports a preview transaction, draft edits update it and Apply commits exactly ONE undo unit while Cancel restores the original and clears the draft; where the engine uses immediate edits + engine undo (`editTextRun` / `editImage` / `updateTextBox` all mutate and push ONE engine undo entry), PRESERVE that model and label the controls `Confirm` / `Cancel` accordingly - never fake transaction semantics by changing DOM text. Document switching and tool switching are handled deliberately (retain draft, confirm discard, or commit by existing policy), never silent loss. Selection alone never marks the PDF dirty (`EngineState.modified` unchanged).
9. **Transforms.** Resize / drag reuse `edit/geometry.ts` (`moveImageRect` `:104`, `resizeImageRect` `:31`, `cropImageRect` `:122`) as device-independent page-point maths with pointer capture (`setPointerCapture` / `pointercancel`) and clean escape on capture loss; aspect ratio follows the REAL modifier / control policy; page boundaries are honoured where required; numeric / keyboard alternatives are exposed in the inspector; object **rotation is NOT supported by the engine** (the only rotation op is per-page quarter turns) and therefore no rotate handle is rendered - it is recorded as a capability-backed extension. Snapping appears only where the engine supports it. Engine coordinate precision is preserved: page-point geometry is never rounded to screen pixels.
10. **Text truth.** Text editing preserves PDF font embedding / substitution rules and the documented embedded-subset feasibility limit (`src/shared/types.ts:1243-1252`; `editTextRun` requires an `EditFont` allowlist and reports substitution only on `replaceText`); the inspector must not present a UI font as the document font, must not advertise editable text merely because pdf.js exposes a text layer, and must explain unsupported text truthfully. UI typography never becomes a document font.
11. **Seams reconciled, never duplicated.** Panels Context Pair (TFL-854) owns the inspector chrome - reuse. Canvas (TFL-858) + Viewing Controls own the viewport and footer transforms - reuse, do not build a second one. Comments and Review / Thread Stream (Phase 116) owns the annotation list / annotation inspector and the single comment entry surface - annotation selection reuses them. Forms and Validation / Guided Fill (Phase 115) owns form filling and validation - field editing stays distinct from object manipulation. Drag Drop and Import / Intake Tray (TFL-1223) owns file intake - object drag stays distinct from page / file transfer. Feedback and Progress / Activity Shelf (Phase 1216) owns async progress / failure - long transforms reuse it. Responsive and Accessibility / Adaptive Shell (TFL-1224) owns global responsive / accessibility rules - apply, do not fork. Print and Output / Output Studio (TFL-1225) shares crop-region / page-geometry semantics - render geometry once, coordinate. Thumbnails and Outline owns the page model - the page-transfer affordance reuses it. Consistency Corrections items 4 (helper typography), 5 (52 px attached-panel header, 40 px navigator view selector), 6 (success / danger palette) and 7 (selection vs status vs navigation ownership) stay in force.
12. **Accessibility, adaptation and pixels.** Complete labels, transient focus / Escape, screen-reader names / roles, forced-colors / high contrast, reduced motion, resize / theme adaptation, long / localized labels, narrow supported windows and 200% scaling are implemented; controls stay above page content and clear of the dock and viewing footer; selecting an object or configuring a view never recolors a PDF pixel or changes document content and UI tokens never replace PDF fonts. Preserve command IDs, session identity, selection identity, undo / draft semantics, keyboard bindings, permission checks, save / close / cancellation policies and native Windows chrome.

9. **Pixels and content.** Selecting an object or configuring a view never recolors a PDF pixel or alters document content.
10. **Accessibility and adaptation.** Labels, focus / Escape, screen-reader names, forced-colors / high contrast, reduced motion, resize / theme adaptation, long / localized labels, narrow windows and 200% scaling hold; controls stay clear of page content, the dock and the viewing footer.
